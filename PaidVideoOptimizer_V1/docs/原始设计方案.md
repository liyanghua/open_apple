# 短视频付费投流优化系统 V1：设计方案

版本：V1.0-设计待确认
日期：2026-09-13
定位：单计划内，单素材排序、独立追投与成本出价建议。
本次交付性质：产品和算法设计；未实现应用，未执行任何平台投放操作。

## 0. 一页摘要

系统回答三个问题：哪些素材值得优先复验／放量；本轮应保持、加预算还是试调成本出价；执行后结果如何、是否应回退。

主流程：上传原始报表 → 确认范围与字段 → 计算指标 → 分组排序 → 最多TOP3 → 补齐追投配置 → 生成限额建议 → 人工执行 → 回收结果。

第一版采用可复算的指标和确定性规则，不依赖语言模型计算分数，不用历史平均ROI冒充新增预算的边际回报。排序分不是成功概率，5%／10%是待验证的试探档位，不是已识别的最优调幅。

### 已确认的业务边界

- 一个计划内有多个素材，且单素材存在独立追投／成本出价入口。
- 排名因子保留30天、7天、近期趋势、稳定性；样本强度与经营底线另行处理。
- 推直播、推商品两个报表可同时导入，但在各自同口径榜单内比较；不把两条路径的收入／费用简单相加。
- 商品价格、商品页、直播话术不作为V1主动优化变量；变化时必须记录为经营条件。
- 先给建议、人工确认与执行，不连接广告账户自动改价。

### 分级可用能力

| 输入情况 | 可计算结果 | 不允许输出 |
|---|---|---|
| 只有30天报表 | 历史ROI、样本、历史候选TOP3、缺失清单 | 伪造7天、连续趋势、稳定性或当前出价 |
| 同截止日30天＋7天 | 近期复验TOP3、前23天粗趋势、诊断与风险 | 已验证的最优调价幅度、真实成功概率 |
| 再补当前单素材任务与授权边界 | 预算／成本出价试探值、金额上限、复核与回退条件 | 仅凭素材汇总保证独立追投的收益 |
| 再积累快照、动作及任务结果 | 不重叠周比较、过线稳定性、动作复盘 | 用滚动窗口差分伪造逐日结果 |

## 1. 数据依据及边界

### 1.1 使用的历史文件

S01：本地私有历史导出（视频→商品，30天）；原始文件名与账户标识不随仓库分发。
S02：本地私有历史导出（视频→直播，30天）；原始文件名与账户标识不随仓库分发。
S03：本地私有历史导出（视频→商品，7天）；原始文件名与账户标识不随仓库分发。
S04：本地私有历史导出（视频→直播，7天）；原始文件名与账户标识不随仓库分发。
S05：本地私有经营基线与口径复核资料，仅用于设计验证，不随仓库分发，也不替换原始导出。

S01、S02 的实际表头用于验证字段映射。原始记录数、账户标识、消耗、成交与净额均属于私有历史经营数据，公开版已删去；完整对账证据保留在本地受控资料中。

验收方法不依赖这些具体金额：在同一导出范围内，分别核对记录数、有消耗记录、集合行、可独立排名的素材数，以及整体消耗、成交与报表净额。集合费用计入全量汇总，但集合行不作为独立素材进入排名。对账结果与源文件哈希绑定，不能把某一客户的金额固化为通用算法预期。

### 1.2 必须保留的口径区别

1. 两份表都有消耗、成交、净成交、净订单，可直接支持基础指标。
2. 推商品表缺曝光、点击和整体成交订单数，相关漏斗指标为空，不影响基本ROI排序。
3. 推直播表除曝光／点击外，还包含“追投调控成交金额、追投调控净成交金额、追投调控净成交ROI、追投调控1小时内退款率”等字段。应保留，但没有完整当前出价、任务预算、任务ID与执行时间，不能单靠这些字段完成调价。
4. 不默认“整体消耗－基础消耗＝独立追投消耗”；不拿已四舍五入的追投ROI倒推精确追投成本。需要字段说明或独立任务消耗。
5. 推直播净额与成交额减1小时退款可逐行核对，不是全部退款成熟后的利润。推商品有1小时退款率，但没有独立1小时退款金额，净额语义仍需确认。
6. 集合ID为“-”，保留费用，对单素材排名排除。报表若同时包含上级汇总和底层明细，必须识别层级后对账，不能全行相加。
7. 同素材可能关联多SKU、甚至历史多计划。用户当前单计划作为工作区配置；无法确认属于该计划的历史混合记录，先保留为历史辅助，不能直接视为当前单计划专属响应。
8. 截至9月8日的报表可用作历史回放；对9月13日或更晚日期的执行建议，需通过数据新鲜度与当前状态检查。

## 2. 产品目标与非目标

### 2.1 目标

- 尽量直接读取现有Excel，不要求运营先改为开发专用模板。
- 每个同口径榜单给最多3条候选及完整解释。
- 明确区分“历史好”“近期值得复验”“当前可执行追投”。
- 所有建议包含原值、新值、限制原因、复核条件、回退值。
- 每次导入、算分、审批、执行和复核可追溯。

### 2.2 V1不做

- 不自动生产或修改视频，不主动改商品售价、承接、库存。
- 不自动登录千川，不发起实际付费操作。
- 不宣称学到了广告拍卖算法，也不宣称精确预测任意出价下的成交。
- 不强行把30天汇总拆成30个日样本。
- 不依靠未经核验的行业均值补字段。
- 不把ROI筛选等同于利润验证，不承诺月销100万元可达。

月销售目标可以配置为经营背景和进度展示；没有成熟全店账本与动作响应时，不让销售缺口自动驱使加大出价。

## 3. 输入合同

### 3.1 文件及导入元数据

每次上传一个或多个原始xlsx。V1优先支持上述两种千川素材导出格式；其他格式先进入手工映射预览。

| 元数据 | 是否必填 | 处理规则 |
|---|---|---|
| 工作区、账户／计划标识 | 是，可人工输入内部标识 | 不从文件名中的长数字猜计划ID |
| 路径：推商品／推直播 | 是 | 可由表头建议，运营确认 |
| 起止日期与时区 | 是 | 从文件名建议，确认后采用；默认工作区时区为Asia/Shanghai |
| 导出／可获得时间 | 是 | 来源有则取来源；否则记录未知并保留导入时间，不伪造导出时间 |
| 成交、净额、订单定义与归因范围 | 是，首次配置后沿用 | 形成basis_id；口径变更不得覆盖旧版 |
| 导出完整性 | 是 | 全量或TOP筛选／部分数据；部分数据不得称全计划TOP3 |
| 版本、文件哈希、原文件名 | 系统生成 | 原文件不可变；同文件重复上传不重复入账 |

两文件“截止日期相同”只是匹配条件之一；还要一致的账户计划范围、货币、路径、归因及字段含义。

### 3.2 报表字段映射

| 标准字段 | 原始字段 | 必要性 | 备注 |
|---|---|---|---|
| creative_id | 素材ID | 单素材计算必需 | 全程字符串，不转浮点数 |
| creative_name | 素材名称 | 建议 | 名称“全部”但ID有效的记录不因名字被删除 |
| version_id | 原文件通常无显式字段 | 可空 | 未知版本标明未知，不自动认定不同ID是同版 |
| spend | 整体消耗 | ROI计算必需 | 不用基础消耗替代 |
| gmv_reported | 整体成交金额 | 支付对照、折减诊断 | 精确保留源语义，不自动认定全为商家实收 |
| net_gmv_reported | 净成交金额 | 默认净ROI计算必需 | 缺失时不能逐行拿支付额替代 |
| net_orders | 净成交订单数 | 主候选样本门槛必需 | 缺失时仍可展示历史ROI，动作降级 |
| reported_roi | 净成交ROI／整体支付ROI | 对账用 | 核心ROI由金额÷消耗重算 |
| impressions | 整体展现次数 | 可选 | 推商品缺少 |
| clicks | 整体点击次数 | 可选 | 推商品缺少，不影响主排序 |
| paid_orders | 整体成交订单数 | 可选 | 推商品缺少，不能用净单冒充 |
| sku_count / plan_count | 素材关联的商品／计划数量 | 可选 | 数量不是具体ID，触发混合范围提示 |
| creation_time | 素材创建时间 | 可选 | 不当首次投放时间 |
| boost_gmv / boost_net_gmv | 追投调控成交金额／净成交金额 | 可选，推直播有 | 不与整体成交重复相加 |
| boost_roi_reported | 追投调控净成交ROI | 可选，推直播有 | 只展示原值，不倒推当前出价和精确成本 |
| source_ref | 文件、工作表、原行、表头 | 系统生成 | 每个派生值可追溯 |

### 3.3 数据校验

- 金额使用整数分或Decimal；保留源值及规范化值。千位分隔符、货币符号、百分号均按字段类型解析。
- 空白／“-”在指标列默认缺失，不全局替换成0；费用为0与费用缺失不同。
- 超长ID保持字符串；数字型ID可能已丢精度时提示重新导出，不猜测修复。
- 同一个窗口、路径、ID的重复行先识别明细维度。只有明确互斥明细才相加；重复汇总不能相加。
- 金额比值重算与源ROI小数位容差不符时发出校验提示；容差随源显示精度配置。
- 消耗0时ROI为空，不产生无穷大；有消耗无成交时ROI为0。
- 净额大于成交、负金额、7天大于30天等需要识别修订／口径／退款原因，隔离有问题的派生计算；不静默截断为0。
- 不以行业参数替代缺失曝光、点击、利润、出价。

### 3.4 追投配置输入

可以单条手填或另导入配置表。数据不齐不阻止排序，只阻止相应数值建议。

| 输入 | 作用 |
|---|---|
| creative_id、boost_task_id、当前状态 | 连接建议与实际独立追投任务 |
| 优化事件：支付订单／净订单／入房等 | 确认成本出价的单位，避免混用 |
| 当前成本出价、允许最高出价、价格步长 | 计算合法的新值；上限必须获批 |
| 任务总预算、已消耗、预计执行区间 | 判断预算限制与剩余风险暴露 |
| 单素材本轮追加上限、剩余试验风险额度 | 限制损失和资源承诺 |
| 账户周期预算、累计实际消耗、已承诺未消耗 | 核算所有TOP3共享的可用预算 |
| ROI筛选底线、口径、来源 | 区分管理阈值和成本推导阈值 |
| SKU／库存／承接是否有效 | 是否允许当前执行 |
| 上次修改时间、最后已验证配置、待复核状态 | 防止连续复利式加价 |
| 当前任务结果、观察成熟度、诊断依据 | 素材整体结果不自动代表独立追投效果 |

缺当前出价时不拿历史CPA代填；缺当前任务预算时不拿7天消耗代填。新建独立任务采用已审批的固定测试额度，不对0预算计算增长百分比。

## 4. 能力模式和队列

### 4.1 模式

| 模式 | 数据 | 评分与输出 |
|---|---|---|
| HISTORY_30D | 只有30天 | F30历史参考榜；无今日放量结论 |
| RECENT_PAIRED | 30天＋7天、前23天可比 | 冷启动分；近期优先复验榜 |
| RECENT_NO_BASE | 7天有结果但前23天不可用 | 新起量／数据不全队列；展示F7，不伪造趋势并混入完整榜 |
| ROLLING_WEEKLY | 具备至少3个可比非重叠周 | 四因子滚动分；标明窗口与成熟状态 |

模式不同的分数不直接混排。主榜按当前工作区选择的统一模式和口径运行；资料不足的素材进入单列队列而非静默删掉。

### 4.2 队列

- 历史候选：仅证明在旧窗口中有参考价值。
- 放量复验候选：近期通过运营门槛，仍需检查当前独立任务。
- 探索候选：小样本高潜、新起量，限额验证。
- 观察／修复：近期未过线、条件变化、结果待成熟等；给原因，不自动暂停。
- 数据待核：范围不明、关键字段缺失、重复或异常。
- 待执行／复核中：已经审批或执行的动作，冻结追加建议直到复核完成。

TOP3是最多3条合格对象，不是必须凑足3条。历史排名与可执行排名分开显示。

## 5. 指标与排名算法

### 5.1 计算难度

D1：报表字段直接计算。D2：少量配置／人工补数。D3：持续积累可比窗口和动作。D4：需要响应模型与实验识别。V1只实现D1、必要D2，以及D3的数据积累与满足条件后的计算；不预填D4结果。

### 5.2 指标目录

记h为7、30或前23天；S为消耗，G为报表成交金额，V为报表净额，Q为报表净订单。

| 编号 | 指标 | 公式或来源 | 用途／难度 |
|---|---|---|---|
| M01 | 30天净ROI | V30/S30 | 历史基础，D1 |
| M02 | 7天净ROI | V7/S7 | 近期效果，D1 |
| M03 | 样本强度 | Q7、Q30、S7 | 门槛与解释，D1 |
| M04 | 平滑ROI | (Vh+s0×Rref)/(Sh+s0) | 抑制小样本极值，D1＋配置 |
| M05 | 近期效率变化 | R7/R23−1 | 趋势；窗口可比才算，D1 |
| M06 | 日均成交／消耗变化 | (V7/7)/(V23/23)−1；S同理 | 解释增长来源，D1 |
| M07 | 成交净额折减 | 1−V7/G7 | 诊断，不叫最终退款率，D1 |
| M08 | ROI底线余量 | 平滑R7/Rmin−1 | 筛选与试探限制，D2 |
| M09 | 实际成本 | S7/Q7；任务则按匹配优化事件计算 | 不与不同事件出价混用，D1／D2 |
| M10 | 任务预算使用率 | 任务消耗/任务预算 | 状态诊断，D2 |
| M11 | 成本出价空间 | qmax/q−1 | 设置上限，不是实际成本保证，D2 |
| M12 | 追加额度上限 | 可用预算／素材授权／剩余试验风险取小 | 共享预算约束，D2 |
| M13 | 周增长 | R7(t)/R7(t−7)−1 | 非重叠周，D3 |
| M14 | 稳定性代理 | 100×ΣSk×I(Rk≥Rmin)/ΣSk | 消耗加权过线率，D3 |

CTR、CVR、曝光与1万+比例是可用时的诊断字段，不必与ROI一起重复高权重加分。

### 5.3 排名参考与参数

Rref采用同工作区、同路径、同成交口径的可比单素材汇总ROI，不拿直播全场包含自然成交的ROI作为素材参考。参考集合及其计算结果随ranking_run冻结保存，不能因筛掉低效素材后重新提高基准。参考组不足时，可用人工批准的参考值；没有参考值则展示原始指标，不伪造平滑分。

s0为平滑强度；100元只作为示例初值，必须允许修改并做敏感性检查，不是最少测试投入。Rmin必须明确来源。首版不默认为所有SKU都应ROI≥5，不把“费比20%”自动换成“净ROI5”：分母口径不同需先对齐。

最近30天与7天重叠，是两种时间观察角度，不是独立样本。保留原权重是运营偏好，不是四份独立证据。

### 5.4 条件派生前23天

S23 = S30 − S7；V23 = V30 − V7。

只有同截止日、同范围、可加总和可比修订口径时计算。差额异常、历史消耗0、缺失近期行等，不填0替代，而是分配缺失原因。无前期有效收入时不使用极小常数计算无限增长。

创建时间不等于开投时间；日均按自然日，不叫有效投放日均。

### 5.5 得分

Fh = 100 × clip(平滑Rh / (2 × Rmin), 0, 1)。

冷启动趋势T = 50 + 50 × clip[ln(平滑R7/平滑R23)/ln2, −1, 1]。

Score_cold = (0.30 F30 + 0.40 F7 + 0.20 T) / 0.90。

滚动趋势改为相邻非重叠周比较。至少3个可比周窗口后：

Score_rolling = 0.30 F30 + 0.40 F7 + 0.20 T_week + 0.10 Stability。

只有30天时：Score_history = F30，并标记历史参考模式。

保留样本量门槛和一次平滑，不再额外乘Q/(Q+10)，避免对同一不确定性重复扣分。分数不代表预测ROI或成功概率。

### 5.6 门槛、同分与稳态保护

放量复验主榜建议门槛：S7>0、Q7≥5、原始R7≥Rmin、平滑R7≥Rmin；关键字段有效、口径可比。5单是首版可调管理门槛，不是统计充分性。

在这些条件外，立即执行还要满足数据新鲜、商品可售、当前任务／出价配置有效、复核完成、经营风险获批。历史数据过线不替代当前任务结果。

同分排序依次使用Q7降序、平滑R7降序、creative_id字符串升序；规则版本固定。榜单变化不自动触发改价，执行冷却不等于把历史结果从排名中删除。

形式化：在合格候选E内选择S，最大化ΣScore_i，且|S|≤3。这是优先级代理目标的最优，不是现实新增GMV的已证明最优。所有数值建议称为试探建议。

## 6. 出价与追投建议引擎

### 6.1 先决定动作种类

| 条件 | 建议 |
|---|---|
| 缺最新状态／出价／授权／观察规则 | WAIT_INPUT，展示排名和待补字段 |
| 数据过旧或仅30天历史 | HISTORY_ONLY，不给今日数值动作 |
| 上次动作未复核 | WAIT_REVIEW，不继续提高出价 |
| 独立任务经济性合格，确认预算限制消耗 | BUDGET_TEST，出价不变 |
| 经济性合格，有成本出价相关诊断且有空间 | BID_TEST，限定额度、预算不同时提高 |
| 预算未用完但原因不明 | HOLD／DIAGNOSE，不把“不花钱”当出价低 |
| 新建独立追投任务，无自身效果记录 | NEW_BOOST_TEST，采用审批固定额度；素材整体排名只是初选依据 |
| 越过风险上限、商品不可售、严重数据异常 | STOP_REVIEW建议，通知人工核查；应用不宣称已暂停平台 |

支持用户确认的成本出价入口。商品售价不变；目标ROI是不同参数类型，未单独配置算法前只记录，不套用“成本出价上调”的公式。

### 6.2 试探幅度

建议首版只提供0%、5%、10%档位。默认第一轮／无稳定性／尚未成功复验时，最多5%；存在可比稳定性及至少一次真实完成的放量复验后，才允许最多10%。

一个可复算的初始限制规则：

H = max(0, 平滑R7/Rmin − 1)

delta_raw = min(delta_evidence, 0.25×H, 10%)

delta = 将delta_raw向下落入{0%,5%,10%}。

其中delta_evidence根据证据档取0%、5%或10%。经营余量只是历史代理，不等于边际回报；上述比例仅是风险控制启发式，不声称最优。正式实现时需把该规则作为policy_version固定。

即使排名高，若无余量、当前独立任务未通过、配置不全或资源不足，也可输出0%。

### 6.3 预算核算

Bfree = max(0, 周期预算 − 已发生周期消耗 − 已承诺未消耗额度)。

对当前任务：Utask = max(0, 当前任务总预算 − 当前任务已消耗)。

若Lremaining为该任务余下允许暴露的毛广告费用，新增风险空间：Ladditional = max(0, Lremaining − Utask)。不靠未经验证的新增收入冲销风险准备。

预算增加量：

ΔB = min(delta×当前任务预算, Bfree, 单素材追加授权, Ladditional)。

Bnew = Bcurrent + ΔB。

新任务无百分比基数时：Bnew = min(审批固定测试额度, Bfree, 单素材授权, Lremaining)。

TOP3共同满足ΣΔB≤Bfree；每笔已审批的在途额度只能预留一次。拒绝／取消／过期后释放未执行预留，已发生费用不能释放。

成本出价提高即使不增加预算，也可能加快既有未消耗额度的使用，必须检查Utask是否仍在风险授权中，不能当作零风险动作。

### 6.4 成本出价

qnew = min(qcurrent×(1+delta), qmax)，按允许价格步长向下取整。

若向下取整后不高于原值，则输出HOLD；若qmax低于当前值，则提示复核／收缩，不生成“加价”。qmax未知则WAIT_INPUT。

actual_CPA_limit与bid_setting_limit单独保存。实际成本上限可以在成本齐全后按以下条件算例计算：

实际每事件成本上限 ≤ min(c−tau×v−o, fbar×v)。

c为该优化事件对应预期成熟商品贡献，v为同事件GMV，o为新增经营费用分摊。这个式子是同口径、不动用旧业务余量下的边界；不能保证平台实际成本等于出价设置，更不能直接跨净订单／支付订单／入房事件替换。

### 6.5 防止连续复利式加价

- 每次动作记录原值、末次已验证配置、审批版本、执行时间和复核状态。
- 导入新数据只更新排名，不自动重复发起同一动作。
- 上次动作未复核，不允许同方向叠加新建议；紧急风险处理单独记录。
- 回退建议回到最后已验证档位，不随意用累计均值生成新锚点。
- 库存、价格、承接或优化目标改变时，对此前动作证据降级，等待复验。

### 6.6 预算协调方式

V1先按排名顺序逐个分配已授权的小额试探，不声称这等于最大化真实成交。如果较低排名对象因剩余预算不足未获额度，明确显示BUDGET_CONFLICT。

每项只允许保持、预算试探、成本出价试探中的一种，避免同时改多变量。对3个对象，基本组合最多3^3=27种，可做规则枚举排除冲突；缺响应数据时不要假装能按预期增量选到真实最优组合。

## 8. 条件算例：用户如何得到一条建议

以下完全是教学数据，不是当前账户实际推荐。

输入历史：S30=3000、V30=18000、Q30=120；S7=1000、V7=7000、Q7=40、G7=8000。配置Rref=3、s0=100、Rmin=5。

计算：R30=6，R7=7，R23=5.5；平滑R30约5.9032、平滑R7约6.6364；原始效率增长27.27%；净额折减12.5%；冷启动分约63.64494。

页面解释：近期量效改善且有40笔近期净单；稳定性未积累，先进行小步复验。分数是优先级，不是63.64%的成功率。

进一步输入当前独立任务：任务预算300元、已消耗285元、成本出价24元、批准上限26元；单素材追加授权100元、账户可用额度150元、该任务剩余毛风险授权50元。另明确当前任务自身结果可观察且过线、商品状态有效、预算限制已确认、无待复核动作。

则历史余量约32.73%，证据上限5%；允许预算试探5%=15元。原未消耗15元，增加后未消耗30元，不超过50元授权。建议为：

- 预算300元→315元。
- 成本出价保持24元。
- 新增预算15元；执行后按配置观察，不同轮连续叠加前必须复核。
- 初步不宣称新增GMV是多少。

如果以上当前任务信息没有提供，只输出该素材的候选资格及待补字段，不输出315元或25.2元。如果预算未用完但未确认限制原因，也不把另一种“出价24→25.2”自动列为应执行动作。

## 9. 技术结构：轻量、可替换、无强制大模型依赖

### 9.1 建议选型

前端采用React＋TypeScript；后端采用Python＋FastAPI；单团队试用阶段用SQLite和受控本地文件目录，按一个模块化单体实现，不拆微服务。数据库与存储适配层预留升级。此处是选型提案，具体版本在实现时锁定。

FastAPI官方文档支持文件上传及SQL数据库接入，适合作为本设计的输入API与配置／快照存储基础。参考R03、R04。V1按Excel上传与人工配置工作，不要求外部广告API。

### 9.2 模块

1. import_adapter：两种源格式、字段映射和元数据。
2. validation：范围、缺失、重复、金额和ID检查。
3. snapshot_store：原文件、规范化快照、as-of版本。
4. metric_engine：M01—M14及质量状态，纯确定性计算。
5. ranker：模式、门槛、分数、同分与解释。
6. recommendation_policy：动作类别、试探档、上限、冷却。
7. budget_ledger：共享授权及在途预留。

语言模型最多帮助解释已经计算出的结果，不产生事实字段、预算、出价、利润认证或“预期提升”。不用模型也应完整运行。

### 9.5 计算难度

固定数量d个指标、N条素材：计算O(Nd)，排序O(N log N)；只维护TOP3时可更低，但无需过度优化。当前几千行级别采用普通确定性处理即可，延迟目标在实现验收时实测，不预先承诺秒数。

困难主要在字段语义、条件可比性、动作效果识别，而不是TOP3本身的计算量。

### 9.6 数据安全

默认原文件和商业数据仅保存在用户选定的运行环境；不向第三方模型上传。原文件只读留存，不能因重新导入覆盖证据。限制文件类型和大小，导入不执行宏或外部公式。导出表格时处理CSV／公式注入风险。任务和动作中不保存广告密码。团队部署再启用鉴权与操作权限。

## 10. 每日运行与学习闭环

1. 导入：今天获得的30天／7天文件，保留所有快照。
2. 确认：报表截止日与原配置变化，检查过旧／退款修订／部分导出。
3. 排名：在统一口径与模式内产生最多TOP3，显示落榜原因。
4. 建议：读取实际任务设置与可用预算，生成至多一次单轴修改建议。
5. 执行：人工确认，记录实际变化值、时间、任务ID；未执行提案不能进入执行效果评估。
6. 复核：先检查费用与数据质量，达到预设观察条件再更新结果与最后已验证档位。

不同阶段结果状态：pending_attribution、provisional、matured、restated。回传成熟与后续退款可以修订结果，但不能倒改当时已知数据和历史推荐。

滚动7天相邻差分不是当天值。日t与日t−7两个7日窗口可形成不重叠周，但还需核对归因修订和信息成熟度。稳定性至少3个可比非重叠周，不把相邻7日快照当3次独立实验。

在没有直接逐日／任务结果时，应用能持续更新候选，不假装识别了某次微调的精确收益。任务结果出现后要比较计划整体和未追投对象，识别潜在替代；没有对照只称观察关联，不称因果增量。

## 12. 迭代与成功衡量

### V1：可计算的排序与追投提案

完成原始Excel导入、D1指标、配置、统一模式TOP3、限额建议、人工执行记录和复核。稳定性具备数据才启用。

### V1.1：实际追投反馈

加入标准任务／逐日结果，区分基础分配与独立追投；统计按建议执行后的过线情况、样本覆盖和风险暴露，校准规则参数。

### V2：约束下的响应优化

在有足够可比动作数据后，估计出价／预算／时长响应与不确定性，从“优先级＋试探”升级为“有限候选中的预测增量最大化”。不要让历史最大消耗等于未来容量，也不要用简单ROI×追加预算称为因果预测。

评价分两层：

- 工程：输入是否正确、计算可复现、推荐有依据、预算预留不冲突、审计完整。
- 经营：与原始7天ROI排序／人工方式比较，后续成熟过线率、能兑现的合格成交、授权损失、无效重复试投是否改善。

按当时可获得数据回放，不能用月底最终退款净额提前重算月中榜单。未经执行的新出价不能靠历史回放证明收益。后续无投放的素材不是零效果，也不能排除后宣称选中者一定更优；记录覆盖和选择偏差，增量效果用可行的小范围对照实验验证。

## 13. 确认后的实现边界

建议确认这一组合：单计划工作区；推商品／推直播分榜；30天直接历史初筛，30＋7近期TOP3；单素材成本出价与预算提案；无平台自动执行；配置缺失明确等待；未来每日保留快照和动作记录。

目标不是一次算出永远正确的出价，而是让每一次“为什么投它、试多少、何时停止、后来怎样”都有可计算依据和可回放记录。
