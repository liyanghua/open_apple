# 实现与原方案对应

## 业务与算法

原设计保存为 `docs/原始设计方案.md`。实现采用原M01—M14定义、一次ROI平滑、原权重、TOP3不凑数、预算／成本出价单轴试探和毛广告风险边界。代码里的引用金额统一整数分，比率为浮点，文件来源与源单元格字符串保留。

`app/importer.py`：以标准库ZIP/XML只读解析XLSX，另支持CSV。没有引入商业表格服务，不执行公式／宏；既保留缺失，也区分0值。多行同ID不随意相加，而是隔离等待明细说明。

`app/engine.py`：指标、四因子得分、模式、分类及追投规则；分数不是概率。核心预测字段 `predicted_incremental_gmv` 和 `success_probability` 保持空值。

`app/storage.py`：SQLite、事务锁、本地额度台账、不可变源文件与审计。

`app/main.py`：文件预览与确认、排名运行、任务配置、推荐、预留、人工执行记录及复核。

`frontend/src/main.ts`、`static/app.css`：六页界面、详情和输入表单。前端为原生TypeScript替代拟议React，服务API仍可由React重接；普通用户不需要Node构建。

## 保守的实现决策

1. 默认ROI 5只是演示管理参数，`threshold_confirmed=false`。未经确认不会给可审批的数值建议。净额定义仍需用户确认。
2. 当前工作区始终显示“ROI筛选／利润未验证”。本版本不把不完整商品成本换算为真实利润通过。
3. 仅30天时可以排序历史值，但不能给今日加价。内置旧数据工作区固定为历史回放。
4. 稳定性需要至少3个连续、同范围、非重叠周。界面需切换到滚动模式，资料不齐的素材进入探索队列，不与完整模式混排。
5. 任务配置必须人工核对且24小时内更新。旧配置或上次未复核不会连续提高出价。
6. 独立任务自身的结果与历史素材结果分开。未到观察期不能直接扩大；新任务按固定授权测试额度。
7. 5%／10%是启发式试探档，低历史余量可能得到0%；源ROI小数显示不改变金额重算。
8. 审批是本地状态变更，不会调用平台。执行记录严格核对批准值；不提供外部账号密码或API密钥入口。
9. 没有全量钱包同步：预算字段说明区分外部发生／承诺与本应用预留／结算，防止人工重复填账。
10. 不可执行的建议仍展示缺少什么，而不是靠假设补成可执行。
