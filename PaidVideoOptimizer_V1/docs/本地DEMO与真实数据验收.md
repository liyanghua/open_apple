# V1.5 日常使用与新品验收指南（评审稿）

**更新日期：** 2026-09-16
**状态：** 以下为待实施流程与验收要求，并非当前页面已全部支持。
**配套：**《乘方协同素材诊断设计》V1.5、《计划加预算与素材复验》升级计划。

## 1. 先准备到哪一步，就使用哪一级功能

| 目标 | 你需要准备 | 输出 |
|---|---|---|
| 新品第一次试投 | 品类、计划标识／本地编号、直播或商品路径、素材清单、总测试金额、日期、每日上限、复核时间、可售状态；ROI 底线确认状态 | 用户额度内的试投安排与采集清单 |
| 看一期素材表现 | 同周期单素材 ID、名称、消耗、净成交、净订单、净额／成本口径和计划范围 | 原始及平滑效率、低样本提示、复验优先级 |
| 按曝光分层 | 上述资料＋每条素材曝光 | 六层分组与目标层内 TOP3 |
| 看内容方向持续性 | 两期不重叠同口径数据、人工标签，且每期满足方向样本条件 | 方向复验；满足规则才扩产或停止复制 |
| 决定计划追加多少 | 最近完整七天每日计划效果、真实日预算及变更、已确认净 ROI 底线、成熟度、追加授权与试验期限 | 计划级金额、期限及复核建议 |

计划汇总不完整时，仍应能看到依据已知字段的素材分析。商品表缺曝光不补零、不虚构曝光层。新品不需要先准备三十天历史。

## 2. 三份填写模板

### 2.1 计划档案（建档一次，设置变化后更新）

| 字段 | 示例／填写要求 |
|---|---|
| 品类 | 毛巾；浴巾、沙发垫另行建档 |
| 计划标识 | 真实计划 ID；没有时明确标为本地编号“毛巾试投01” |
| 路径 | 视频到商品／视频到直播 |
| 预算 | 日预算或总预算、金额、步长、生效日期；金额单位元 |
| 后台目标 ROI | 原后台数值及口径，不自动当本地净 ROI 门槛 |
| 本地最低净 ROI | 业务确认值；不知道就填待确认，不能沿用演示 5 |
| 成本与净额口径 | 原始字段、退款窗口、佣金是否包含、未知项 |
| 营销能力与经营状态 | 实际开关、可售／库存／承接状态及核对时间 |
| 试验授权 | 总额、授权周期、单次新增上限、试验天数、复核时点 |

截图佣金显示“—”时填写未知，不据此勾选仅基础投放。预算和 ROI 数据未知不允许代填历史推测值。

### 2.2 每日计划记录（一计划一路径一天一行）

必填：日期、计划标识、路径、有效预算、消耗／综合成本、净成交金额、净订单、导出时间、净额与成本口径、观察成熟状态。

可选：用户实际支付净成交、佣金、曝光、点击、库存／商品／ROI 目标变更说明。计划设置变化需保留生效时点。

七天截图只能保存为周期汇总，不均摊成每日实绩。跨午夜按统一时区统计，优先从次日完整预算日开始试验。

### 2.3 每周素材明细（一计划一路径一素材一周期一行）

必填：计划范围、路径、起止日期、素材 ID、名称、消耗、净成交金额、净订单、字段口径。

功能补充：曝光用于分层，点击用于漏斗，上线时间用于辨认新素材；内容类型、开场钩子、核心卖点用于方向聚合；视频或人工描述用于内容分析。

同名不同 ID 不合并，同 ID 在不同计划或路径分别记录。集合行保持集合，不伪装成素材。报表无计划 ID 时使用人工范围确认，来源信息保留。

## 3. 周期与每天／每周怎么用

前一期示例：连续完整的第1周。
当前期示例：紧接第1周、没有重叠日期的完整第2周。

计划汇总与分素材明细必须匹配周期、路径和口径；尽量同次导出，避免归因／退款更新产生额外差异。若两个窗口共享任一天，就不能作为独立前后周比较。

每日更新计划实绩和设置，先处理数据／经营异常，再查看是否有预算试探条件。每周更新素材报表、复验优先级和内容标签，安排一个变量的变体。人工执行后登记真实设置，到期复核，不能把点击“确认”当作后台已执行。

## 4. 毛巾新品最小启动实例

输入：毛巾、视频到商品、六条素材、七天、总试投上限 700 元、日上限 100 元、复核时间和可售状态；本地净 ROI 底线填写业务值或待确认。

系统应能生成初始限额安排和记录清单，不把 700 元均分给素材，不根据桌垫历史预测成交。此金额仅作填表示例。

第一周：每天上传／录入计划数据；部分周期提示继续采集。七天后导入素材表，即使缺曝光也显示 ROI／净订单诊断。底线未确认或归因未成熟时，不生成新增预算金额。

第二周：导入可比数据，判断复验对象及内容方向；两期均满足样本和方向规则后才扩产。浴巾和沙发垫采用相同流程，但独立计算参考值与底线。

## 5. 私有历史样本验收方法（数值已删去）

原验收样本的账户、日期和经营数值仅保留在本地受控资料中。公开版列出同一套检查条件，不包含客户实绩。

| 场景 | 通过条件 |
|---|---|
| 商品整体截图 | 原样保存同范围成本、报表净成交、净订单和 ROI；另存实际支付净成交，不互相替代 |
| ROI 口径 | 用同范围报表净成交÷成本复算；不使用实际支付金额替换分子，不把实绩设为门槛 |
| 商品视频子集 | 保存含集合子集的成本、净成交和订单；显示与整体差额，不强行对齐 |
| AIGC 排除 | 排名排除集合，普通素材按原范围独立计数；集合费用和成交仍可追溯 |
| 直播明细 | 直播普通素材有曝光／点击时保留；不引用商品截图作为直播整体 |
| 人工范围确认 | 标记用户确认单计划，保留原始关联计划数量；不猜文件名中的数字为计划 ID |
| 缺曝光 | 商品可显示订单／ROI 分析，曝光显示未知，不占用已有曝光层 |
| 真正 TOP3 | 各层各目标只选可计算的前三条，同分稳定；全量仍可查，集合不占名额 |
| 低样本与零值 | 实际零订单保留零；零消耗效率不可计算，未知不补零，平滑显示依据 |
| 周比较 | 一期可诊断；重叠周不能作周增长；两期方向样本需分别达标 |
| 新品隔离 | 毛巾、浴巾、沙发垫不沿用桌垫 ROI／转化率基准，零历史也有可用启动流程 |
| 日预算试验 | 7天数据、新鲜度、成熟度、预算限制及授权全部满足后才给金额；输入条件缺失逐项说明 |
| 金额单位 | 历史复用填 100 元，存储为 10,000 分；前后端不得重复乘 100 |
| 预留与复核 | 重复／并发确认不超额；未复核不连续追加；到期不宣称自动回退、不擅自释放未关闭额度 |
| 历史兼容 | 旧文件和快照保持原值、原版本，刷新可恢复；旧数据不能冒充今日实绩 |
| 服务上线 | 实际服务加载新接口和新前端；不以单独构建成功替代页面验证 |

证据要求：保留导入来源／校验值、数据及规则版本、诊断快照 ID、页面截图、授权变更记录和实际测试结果。经营效果仍需真实后续数据检验。

# V1.4 历史使用与验收指南

以下保留旧版本流程，便于理解现有实现。其全量成本强制对账、曝光统一必需和仅内容建议的限制，不作为 V1.5 新功能的验收条件；旧独立追投流程仅适用于真实存在独立任务的场景。

# 本地 DEMO 与真实数据验收

## 本地入口

- 地址：http://127.0.0.1:8765 （启动窗口显示的地址为准）。
- 再次启动：双击项目目录中的 `启动-Mac.command`，或在该目录执行 `bash start.sh`。保持启动窗口打开。
- 数据保存在 `data/`，关闭应用后仍保留。备份时停止服务，再复制整个 `data/` 文件夹。

## 先体验教学闭环

1. 点击左下角“体验教学模拟”。每次点击会创建一个新的教学工作区。
2. 在候选榜点击“生成追投建议”。默认教学数据应只出现两个合格候选，其他素材进入探索、观察或无消耗队列。
3. 核对教学 A：预算 300 → 315 元，成本出价保持 24 元，追加预留 15 元。
4. 核对教学 B：成本出价 20 → 21 元，预算保持 500 元，新增预算预留 0 元；仍检查既有未花预算风险。
5. 点击“批准并预留”，在“追投与复核”记录模拟执行。
6. 填写模拟观察结果并复核。教学工作区允许提前演示成熟复核，真实工作区需要等待复核窗口。

以上只写本地教学记录，没有实际广告操作。已执行的教学动作会保留状态；希望从头体验时再次创建教学工作区。

## 真实数据准备

建议先准备同一账户／计划、同一截止日的四份原始报表：

| 文件 | 需要确认 |
|---|---|
| 推商品 30 天 | 导出起止日期、原始全量范围 |
| 推商品 7 天 | 与对应 30 天同截止日、同范围、同净额口径 |
| 推直播 30 天 | 单独核对，不与推商品合并计算 |
| 推直播 7 天 | 与对应 30 天同截止日、同范围、同净额口径 |

保留原始 XLSX、表头、素材长 ID 和所有行；无需先转成模板。请一并说明账户／计划标识、报表时区、是否全量、净成交与退款定义、归因范围。只有 30 天也可以先验收历史排序。

要验收具体追投建议，另准备候选素材的当前独立任务配置：任务 ID、优化事件、出价类型、当前出价／上限／步长、任务预算／消耗／自身净成交、结果成熟状态、预算或出价限制依据、追加授权／风险额度／复核时间，以及商品和承接条件是否变化。工作区还需要确认 ROI 管理筛选线及预算池授权、其他已消耗、其他在途授权。

## 验收顺序与通过条件

在新建的真实工作区导入，不使用“教学模拟”或“历史样本”工作区承载新的正式数据。

| 步骤 | 核对内容 | 通过条件 |
|---|---|---|
| 1. 导入与对账 | 原始行数、消耗、成交、净额、有效单素材数 | 与同口径原表汇总一致；差异能追溯到原行 |
| 2. 字段与范围 | 19 位 ID、集合行、日期、路径、净额定义 | ID 不损失精度；集合保留费用但不当单素材；范围经确认 |
| 3. 排名 | 每条候选的公式、门槛、近期订单、趋势 | 可手工复算；不足三条不凑数；零消耗与小样本正确分层 |
| 4. 不匹配与缺失 | 仅 30 天、截止日不匹配、缺当前任务配置 | 不伪造趋势或具体新出价，页面明确说明缺失条件 |
| 5. 建议 | 原值、新值、金额上限、复核与回退条件 | 只改获准变量，不超授权；历史数据不能被当作今天有效配置 |
| 6. 本地审批 | 重复点击与多素材共享额度 | 不重复预留、不超总授权；审批不调用广告平台 |
| 7. 执行与复核 | 人工平台操作后的真实记录、同批结果、预算结算 | 记录与批准值一致，观察期不连续加价；结算和释放可对账 |
| 8. 留档 | 排名 CSV、指标 JSON、工作区归档 | 保存当时输入、参数、建议和审核记录，支持之后复盘 |

当前阶段先验收工程闭环。经营效果需要实际执行后的成熟结果和可比对照，不能凭教学数据或历史排序证明。内置 ROI 5 是演示管理参数，真实工作区应按业务口径确认。

## 乘方协同模式：真实数据导入清单

乘方协同与上面的“独立追投”验收是两条明确选择的工作流。进入工作区时先选择模式；不要把旧独立任务配置、跨期累计数据或教学数据当作乘方素材诊断输入。

开始导入前，运营人员应确认并留档以下项目：

1. 一个已冻结的 7 天素材快照：同一计划、同一投放路径（推直播或推商品）、同一乘方分区、相同起止日期和时区。每条素材须有可归属整体消耗、净成交金额、净订单和曝光。
2. 同一期间、同一计划的营销整体消耗。素材可归属消耗之和须与该总额对账，差异不超过 `max(¥1, 计划整体消耗 × 1%)`；超过即停在对账，不做素材或素材组 ROI 结论。
3. 完整计划上下文：计划 ID、路径、乘方起始日、当前综合营销 ROI 目标、计划状态、净额／归因定义，以及数据分区。
4. 完整营销能力标记：基础投放、星选、达人营销、含达人佣金出价等开关；确认整体消耗是否已纳入对应营销成本。
5. 10–20 条素材的人工内容标签。每条至少填写内容类型、首屏钩子和核心卖点；人物、场景、价格表达、时长可作为补充标签。不得由文件名推测标签。
6. 同周期操作日志：ROI 目标、预算、营销能力开关、商品／承接变化的时间和说明。日志用于解释背景，不能把相关性写成因果。

只有整体总计、没有单素材可归属成本的数据，仍可核对计划规模和综合营销 ROI；它不能支持单素材或素材组 ROI，也不能导出内容方向的 ROI 结论。`overall` 或跨分区汇总只保留消耗、成交和订单等规模指标，不计算 ROI。

## 从独立追投迁移到乘方协同

迁移前应在业务低峰完成以下清单；它保留可恢复证据，但不会把历史独立追投结论改写成乘方结论。

1. 停止本地应用，完整复制 `data/` 目录到一个可识别的恢复备份位置，再启动应用。JSON 导出仅供审计阅读，不能替代整个 `data/` 恢复备份。
2. 在新工作区中显式选择“乘方协同”模式；旧工作区继续以“独立追投”模式只读复核，避免混用规则。
3. 保存计划上下文和全部营销能力开关，确认素材数据分区、同计划同路径范围和成本口径／对账结果。
4. 为 10–20 条试点素材补齐人工标签；先以低样本限制运行，缺数据或未对账时只允许补数据、观察或补测。
5. 生成首份诊断并冻结其输入、阈值、标签和操作日志版本。观察期内不根据本地诊断改变计划预算、ROI 目标、出价、营销能力或素材状态。
6. 由运营人员记录实际的内容上新、变体制作和任何计划级人工操作；这些记录与诊断快照一起保存。
7. 观察期结束后，导入相同计划、路径、分区和口径的下一非重叠周期，或用已冻结快照回放。仅在可比较数据满足规则时评估方向是否持续。

## 乘方协同验收步骤与证据

| 步骤 | 核对内容 | 通过条件／应留证据 |
|---|---|---|
| 1. 模式隔离 | 旧独立追投工作区与新乘方工作区并存 | 旧流程仍可读取、复核和本地审批；乘方工作区不出现单素材预算／出价提案 |
| 2. 分区与范围 | 同计划、同路径、同乘方分区、相同 7 天窗口 | 导入确认页与冻结快照显示范围；不同分区或路径不得生成合并 ROI |
| 3. 成本对账 | 素材可归属消耗、计划整体消耗、差额 | 保存原始行、对账值和阈值；差额超过 `max(¥1, 1%)` 时阻断 ROI 诊断 |
| 4. 综合成本口径 | 达人佣金等营销能力开关和成本包含关系 | 缺少综合成本口径时明确标为基础投放成本，不能伪称综合营销 ROI |
| 5. 样本限制 | 低曝光、低消耗或一个有效周期的素材 | 只输出继续观察／补测，不输出停止生产／扩产；保存曝光层和冻结阈值 |
| 6. 冻结回放 | 输入、上下文、能力、标签、阈值和操作日志版本 | 后续修改标签或设置后，历史回放仍显示原快照结论和来源 |
| 7. 提案冲突 | 对已失效或不满足前置条件的提案提交审批 | 服务返回 409，且不创建审批、预留或计划变更记录；保存响应和前后状态 |
| 8. 本地边界 | 导入、诊断、审批和回放操作 | 应用只写本地 `data/`；不登录千川、不调用外部平台接口、不自动改计划或素材状态 |

建议在每次正式验收中附上：导入文件的校验值或受控存储位置、诊断快照 ID、对账截图／导出、回放截图、409 响应体，以及操作日志的人工签名或责任人记录。真实经营效果仍需同口径的后续成熟数据和业务对照验证。
