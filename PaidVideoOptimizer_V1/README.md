# 投流实验室 · 短视频付费投流优化系统 V1

> 最新更新：支持最近7天曝光500／1000／2000／5000分层，默认显示5000次及以上的层内TOP3；可切换任一层或全部曝光。曝光样本量不是统计置信度。见 `docs/曝光分层规则.md`。

> 2026-09-13 更新：当前采用 **全量评分 TOP3**，按用户要求取消排名前的 ROI／订单／样本量筛选。所有独立素材参与打分，原有队列仅作为数据与追投状态；缺失项只在评分层用参考值补齐。后文关于“过线才入榜”的旧版描述已被本规则替代，详见 `docs/全量评分规则.md`。追投审批与预算检查仍单独执行。

**可以运行的本地应用，不是页面原型。**

导入原始30天／7天Excel → 查看最多TOP3及指标解释 → 填写单素材独立追投配置 → 生成预算／成本出价试探建议 → 本地审批与预留 → 人工到平台执行 → 记录结果与复核。

系统不会连接广告账户，不会实际下单、追投或修改出价。无模型API Key要求。

## 1. 最快启动

### Mac

1. 解压整个文件夹，不要只取 `index.html`。
2. 已安装 **Python 3.10或更新版本**时，双击 `启动-Mac.command`。
3. 首次安装Python依赖需要网络；以后同一环境运行不用网络。
4. 浏览器会打开本地地址，通常为 `http://127.0.0.1:8765`。端口占用时自动尝试后续端口。

如果系统不允许双击启动脚本，在终端进入解压目录后运行：

```bash
bash start.sh
```

### Windows

安装Python 3.10或更新版本后，双击 `启动-Windows.bat`。首次启动安装依赖，之后自动启动浏览器。

### 已有Python环境／Linux

```bash
python -m venv .venv
# Mac / Linux
source .venv/bin/activate
# Windows 使用 .venv\Scripts\activate
python -m pip install -r requirements.txt
python run.py
```

启动窗口需要保持打开。按Ctrl+C或关闭窗口停止服务。界面不依赖Node、npm、外部CDN或大模型。需要更换端口时：

```bash
python run.py --port 8866
```

本交付在Linux、Python 3.13环境和Chromium中完成测试；提供了Mac／Windows启动脚本，但没有声称在实体Mac／Windows机器上测试过。若Python低于3.10，请先升级；初次依赖安装失败时，应保留报错，不要把页面当作已启动。

## 2. 第一次使用建议

### A. 先查看合成示例

首页点击 **“载入合成示例”**。

会创建独立的“合成30天／7天示例”工作区，并导入包中四份虚构 CSV：商品与直播各有30天和7天窗口，截止日均为2025-01-30。素材ID、名称和金额均为演示数据；真实报表需在“导入与对账”中由用户自行导入。点击两条路径切换、查看全量表与指标详情。内置ROI 5、平滑100元只是演示管理参数，不代表商品盈利底线；实际规则应由业务确认。

**这个工作区永久标为历史回放，不批准当前投放动作。** 合成集合行保留费用，但不当独立素材；不足三条过线就不凑数。

### B. 体验完整追投流程

点击 **“创建／体验教学模拟”**。

系统生成一个明确标记的模拟工作区，包含6个教学素材、30天／7天和另外三个非重叠周快照，以及两条已填写的模拟任务。默认冷启动模式下：

- 教学A的预算建议为 **300元→315元，出价保持24元**；
- 教学B的成本出价建议为 **20元→21元，预算保持500元**。

操作顺序：生成追投建议 → 本地批准 → 记录平台已执行（模拟中只是体验）→ 填写后续观察结果 → 复核。

教学工作区允许提前演示成熟复核；真实工作区必须等到约定复核时间。模拟数据和配置不会复制到你的正式工作区。

### C. 导入你自己的新数据

新建“我的投流”工作区，在“导入与对账”中选择或拖入原始 `.xlsx` / `.csv`。

逐份确认：成交路径、起止日期、净额口径、账户／计划范围、是否完整导出。系统先显示对账与错误；必要字段不认识时展开字段映射。

文件支持前30行内的表头，最多50,000行、200列，单文件20MB；只读标准XLSX，不执行宏、外部公式或Excel缓存重算。标准CSV模板在页面内可下载。

**仅30天也可工作：**在TOP3工具条将7天选为“不使用7天”，查看历史参考榜。

**30天＋7天：**应为同一路径、同截止日期、同范围和口径。否则不计算23天差额及趋势。不从30天汇总伪造逐日数据。

## 3. 配置排序规则

“策略与预算”中可修改：

- 报表净ROI筛选线及来源说明；
- 近期净订单门槛（初值5，管理规则而非统计充分性）；
- 平滑强度，参考ROI可固定或由同路径单素材汇总；
- 新鲜度上限；
- 30天、7天、趋势、稳定性的权重。

默认规则：一次ROI平滑；冷启动按30/40/20归一；具备至少三个连续可比非重叠周后，选择“滚动周”才启用30/40/20/10。不同评分模式的对象不混入同一主榜；小样本、新起量、缺字段均单列。

确认筛选线不会自动变成利润认证。此版工作在 **ROI筛选模式**，没有完整SKU成本和退款成熟数据时，不计算“真实盈利已通过”。

## 4. 生成实际数值建议

点击素材卡“配置追投”。必须填写当前独立任务，不拿素材整体历史代替：

- 任务ID或内部唯一标识、优化事件与成本出价类型；
- 当前出价、获批上限、价格步长；
- 当前任务预算、已消耗及任务自身净成交金额；
- 净额口径与观察状态；
- 单素材追加授权、剩余毛广告风险额度、复核小时；
- 商品／SKU／承接／当前配置有效性；
- 预算限制或出价限制的诊断依据。

已有任务：需要自身结果已到观察期且通过管理线。新任务明确填预算和已消耗0，并审批固定测试额度；不按0预算算5%。

**保持／等待是正常输出。** 缺配置、旧数据、低样本、未观察完、额度不够、条件异常时不生成虚假动作。预算没花完不等于成本出价低。仅支持成本出价调节；目标ROI模式只记录，不套同向调价公式。

## 5. 本地预算账怎么填

工作区使用整数分计账；界面按元填写、展示。

- **预算池总授权：**这份本地台账管理的总金额。
- **其他已消耗：**已经发生，但**不含本应用中已结算追加授权**的金额。
- **其他在途授权：**既有任务尚未花出的预算，**不含本应用中的预留**。
- 本应用预留：由批准动作自动产生；不会三条素材重复使用一笔钱。
- 本应用已结算：复核时填写的、该笔预留之内已实际发生的费用。

可用额度＝总授权－其他消耗－其他在途－本应用在途预留－本应用已结算。

**不是平台钱包同步。** 其他费用需要人工按相同范围核对。若从平台汇总中录入全部消费，必须先扣除本应用已结算部分，避免重复。当前任务未花额度也需要纳入“其他在途授权”或已经由本应用占用，不应漏记。

增加成本出价即使不增加预算，也要检查当前任务剩余未花额度是否在毛广告风险授权内。

## 6. 审批、执行、复核

1. **生成提案：**不预留、不执行。相同输入重复点击不会重复建立同一提案。
2. **本地批准：**再次检查条件并事务性预留。提案有效期2小时；配置变化后应重算。
3. **人工执行：**到实际平台操作，再回来录入。记录值必须与批准方案一致。系统不发起平台调用。
4. **观察中：**该素材不再生成同方向连续加价。取消只适用于未执行提案；已花费用不能通过取消释放。
5. **复核：**可先保存待归因／临时观察。达到约定窗口后记录同批消耗、净额、净订单、说明，并结束该笔追加授权。
6. **结算与回退：**已花部分计入本地结算，未花预留释放。未通过时给出最后已验证值的回退提示，由人操作。下一轮前重新核对当前任务配置。

“同批观察过线”不等于证明因果增量。复核金额与素材整体30天成交不混用。任务和平台的范围若发生变化应重新建立对照。

## 7. 保存与导出

- `data/optimizer.sqlite3`：工作区、指标、排名、任务、动作、审核与审计。
- `data/raw/`：原始上传文件，以哈希命名，原文件名及原行位置保存在记录中。
- 导出排名CSV、完整指标JSON、工作区JSON归档。
- 完整恢复最可靠的方法：停止应用后备份整个 `data` 文件夹。单独JSON为可检查归档，本版本没有JSON一键恢复入口。
- 可通过环境变量 `OPTIMIZER_DATA_DIR` 指定数据目录。

原始文件只读留存，同文件重复导入不重复计数。错误范围已确认时不会覆写旧证据；应在新工作区重新确认正确范围，保留原记录用于对账。

## 8. 已实现与尚未实现

**已实现：**原XLSX/CSV导入、手工映射、确认与对账、长ID保留、分路径指标、历史／近期／非重叠周排序、最多TOP3、原行追溯、单素材配置、0/5/10%边界试探、共享预留、本地审批、人工执行记录、复核及回退建议、快照／审计、CSV／JSON导出、合成示例与教学模拟。

**未实现也未声称：**广告平台接口、自动追投、最优拍卖出价、可靠增量GMV预测、成功概率、完整成本利润认证、自动视频生成、自然流量外推、多用户鉴权与公网部署。

技术实现采用 **Python＋FastAPI＋SQLite后端，原生TypeScript前端（已编译）**。相较设计中的React建议，交付层改为无React运行时依赖的本地前端；页面、算法、接口和状态流程保留。TypeScript源码与构建配置包含在包内，普通使用不需要构建。

## 9. 测试与开发

```bash
python -m pip install -r requirements-dev.txt
python -m unittest discover -s tests -v
```

前端已经预编译。修改TypeScript后需要TypeScript 5.8.3：

```bash
cd frontend
npm install
npm run build
```

接口定义可在运行后访问 `/api/openapi.json`。浏览器测试说明见 `docs/测试报告.md`。默认只绑定127.0.0.1，并校验Host／同源写入；此版本不适合直接暴露公网。团队部署需要再增加登录、权限、HTTPS、备份和更严格的审计。
