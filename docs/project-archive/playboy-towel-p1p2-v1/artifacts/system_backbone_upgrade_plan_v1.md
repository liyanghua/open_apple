# 300条视频方案 × 当前主线链路：系统主干升级规划

版本：v1.0
依据：

- `花花公子毛巾_300条_V2/完整方案_300条_V2.md`
- `artifacts/batch_production_plan_v2.md`
- `artifacts/visual_sellpoint_spec.md`
- P1/P2 首轮样片与参考视频分析结果

## 一、结论

当前主线已经能完成单条样片，但还不能稳定支撑 300 条去重成片。主要缺口不是再增加一个生成模型，而是把“事实、卖点、素材、实验、版本、审核、发布、复盘”串成可追溯的生产数据链。

需要把现有链路从：

```text
选商品 → 写脚本 → 生成素材 → Remotion合成
```

升级为：

```text
商品事实准入
→ 需求/购买理由
→ 内容配方与控制变量
→ 主图卖点矩阵
→ 素材召回与缺口分析
→ Seedance动作片
→ TTS/字幕/BGM
→ Remotion品牌合成
→ 自动QA与人工审核
→ 发布/实验记录
→ 数据与经验回写
```

## 二、300条方案对系统主干提出的硬要求

300条不是简单扩大产量，而是四种数量账同时成立：

- 4周 × 每周75条
- 240条实验 + 60条支持内容
- 6个主方向配额
- 3个主商品配额

因此系统必须同时识别：

1. 这条视频属于哪个 SKU、事实版本和实验组。
2. 它相对父版本改变了哪个变量。
3. 它是否是真正去重内容，而不是换封面或重新导出。
4. 它使用了哪些主图、动作、口播、BGM 和声明。
5. 它是否通过商品事实、视觉、权利、编码和人工审核。
6. 它发布后对应哪个发布/投放 ID 和数据窗口。

## 三、主干升级清单

### 升级1：商品事实卡从静态 JSON 升级为版本化事实服务

当前已经有 P1/P2 事实卡，但批量需要：

- `product_id`、SKU、规格、颜色、价格、库存、更新时间
- 声明类型：页面标注、实测观察、独立证据、主张、偏好
- `claim_id`、证据 ID、适用 SKU、允许措辞、禁止措辞
- 权利状态和失效时间
- 事实版本号
- 受影响成片列表

系统行为：

- 事实版本变化时，自动标记受影响脚本和成片待复核。
- 页面动态价格不进入长期文案缓存。
- 缺证据的声明不能进入发布状态。
- 事实卡成为 TTS、字幕和 Remotion 的唯一文案输入。

### 升级2：增加“需求—卖点—证据—动作”内容配方层

300条方案不是随机组合 D×P×I×S。新增 `content_recipe`：

```json
{
  "recipe_id": "P2-weave-touch-v1",
  "sku": "yb-bb-12",
  "need_id": "D01",
  "structure_id": "P1",
  "ip_persona_id": "I01",
  "selling_point_id": "10-C01",
  "evidence_ids": ["E-P2-page-001"],
  "visual_action": "weave_touch",
  "control_variables": {
    "sku": "fixed",
    "fact_version": "fixed",
    "opening": "variable",
    "camera": "variable"
  }
}
```

这样系统能明确区分母题、版本、变量和素材，而不是只保存一条视频文件。

### 升级3：建立主图卖点矩阵和素材槽位系统

每张主图必须绑定：

- 商品 SKU
- 视觉用途
- 一个主卖点
- 允许的口播措辞
- 推荐动作
- 禁止动作
- 证据等级
- 是否含真人、Logo、嵌字和隐私风险
- 是否适合作为 Seedance 参考图

动作槽位统一为：

- `product_full_view`
- `weave_macro`
- `touch_brush`
- `lift_unfold`
- `fold_fall`
- `color_reveal`
- `use_context`

系统先召回已有素材，再判断是否需要 Seedance 或补拍，落实“先复用，再补拍，最后生成缺口”。

### 升级4：把 Seedance 从单次调用升级为可重试的动作生产器

Seedance 任务需要保存：

- 输入主图和事实参考图
- Prompt 版本
- 模型、provider、时长、分辨率、比例
- 任务 ID、成本、失败原因
- 首帧/中帧/尾帧检查结果
- 商品身份评分
- 动作完成评分
- 是否进入正式素材池

错误必须分类：

- 输入尺寸/比例错误
- 真人隐私拦截
- 商品身份漂移
- 构图失败
- 动作不完整
- 纹理或颜色变化
- 供应商/API 错误

重试只能针对明确问题修改，不允许无原因重复生成。

### 升级5：Remotion 从“单条合成组件”升级为模板化编排器

应拆成四层：

1. `BrandLayer`：Logo、字体、字号、安全区、强调线。
2. `ShotLayer`：动作片裁剪、速度、交叉淡化、画面切换。
3. `SpeechLayer`：TTS 音频、时间戳、语义字幕。
4. `AudioLayer`：BGM、ducking、淡入淡出、响度控制。

模板必须只接受结构化 props：

```json
{
  "shots": [],
  "captions": [],
  "logo": {},
  "voice": {},
  "music": {},
  "slogan": "PLAYBOY，让日常更有质感"
}
```

禁止在成片模板中手写商品事实、货号、动态价格或临时字幕。

### 升级6：把高密度切换变成正式时间线能力

当前已经验证参考片的高密度节奏：约2秒一个卖点。系统应支持：

- 镜头时长 1.5–2.2 秒
- 4–6 个卖点镜头
- 4–6 帧短交叉淡化
- 片尾 0.8–1.2 秒品牌收束
- TTS 时间戳驱动字幕和镜头切换
- 口播结束后至少留 0.5 秒余量

切换必须使用统一时间线，不再手工拼接不同长度的片段。

### 升级7：音频链路分离并统一混音

- Doubao TTS 单独保存音频和时间戳 JSON。
- SUNO BGM 单独保存曲目、提示词、模型和授权状态。
- 混音保存人声、BGM、最终音轨三个版本。
- 口播优先，BGM 默认低于人声约 15–20 dB。
- 若口播时长超出画面，系统自动延长品牌收尾画面，不截断尾句。

### 升级8：增加五层 QA 门

#### A. 事实 QA

声明、SKU、颜色、规格、价格和事实版本一致。

#### B. 视觉 QA

Logo 只出现一次，标题不重叠，字幕不出安全区，字体和字号符合规范。

#### C. 动作 QA

商品不变色、不变形、不串 SKU，动作完整，切换不闪烁。

#### D. 音频 QA

口播完整，字幕同步，人声清晰，BGM 不盖住口播。

#### E. 编码 QA

H.264 High、`yuv420p`、AAC-LC、MP4、1080×1920、30fps，可被目标播放器打开。

### 升级9：增加版本和实验追溯链

每条成片必须有：

```text
experiment_id
→ content_version_id
→ parent_version_id
→ changed_variable
→ recipe_id
→ sku/fact_version
→ claim/evidence IDs
→ source asset IDs/timecodes
→ model/tool versions
→ QA results
→ human approval
→ publish/ad IDs
→ data window
→ conclusion
```

缺少这条链的成片只能算草稿，不能计入 300 条正式交付。

### 升级10：增加批量去重和疲劳控制

系统要同时做三种去重：

- 内容去重：购买理由和镜头动作不能完全相同。
- 素材去重：不能只换封面或文件名。
- 实验去重：同一父版本的近似开场不能重复计数。

允许变化：

- 开场问题
- 第一动作
- 镜头顺序
- 口播密度
- 生活情境
- BGM 节奏

不允许随意改变：

- SKU
- 商品事实
- 主体证据
- 交易承诺
- 品牌视觉规范

## 三点五、300条方案中的“视频类型”如何进入系统

《完整方案_300条_V2》中的视频类型不能只作为选题标签保存，而要进入内容配方、镜头模板、素材需求、审核规则和实验统计。系统为每条内容同时保存以下字段：

```text
direction_id       主方向：实测/治愈/关系/空间/评论/交易
structure_id       内容结构：P1—P6
support_type       实验/信任/答疑/承接
need_id            用户需求与情绪变化
sku                主商品
recipe_id          具体内容配方
```

### 1. 六个主方向映射

| 方案中的类型 | 系统中的 `direction_id` | 常用结构 | 主要素材槽位 | 质量重点 |
|---|---|---|---|---|
| 实测与选购 | `test_selection` | P1 真实验证、P6 选购解释 | 全貌、标签、尺寸、织纹微距、真实动作 | 条件、证据、结果边界必须说清，不能把演示写成检测 |
| 治愈微仪式 | `healing_ritual` | P2 生活微仪式 | 展开、触摸、擦拭、折叠、挂好 | 情绪服务于商品动作，不能只做氛围片 |
| 关系微故事 | `relationship_story` | P3 关系微故事 | 准备、取出、留挂位、递给他人 | 商品必须参与关系行为，不能用关系焦虑逼单 |
| 空间与玩趣 | `space_play` | P4 空间微改造、P5 轻玩趣 | 同机位前后、配色、收纳、局部变化 | 只能把真实变化归因于毛巾，不能同时换一堆布景 |
| 真实评论与答疑 | `comment_faq` | 按问题选择 P1/P2/P6 | 评论截图、对应商品细节、回答动作 | 没有真实评论不能伪造；每条必须绑定问题来源 |
| 交易与直播承接 | `transaction` | P6 承接/真实使用 | 当前商品页、规格颜色、使用结果、品牌收尾 | 价格、库存、优惠和链接必须来自当前事实，不缓存旧信息 |

### 2. “实验”和“支持”是任务属性，不是第七种视频类型

300条方案里的 240 条实验和 60 条支持内容，系统用 `support_type` 标记：

- `experiment`：有明确父版本和一个主要变化变量，用于回答经营问题。
- `trust`：补充证据、细节和信任，不要求每条都直接转化。
- `faq`：回答真实评论或客服问题。
- `transaction`：讲清当前商品、规格、颜色、价格或去向。

同一个主方向可以属于不同任务属性。例如“实测与选购”既可以是实验，也可以是信任支持；“评论答疑”通常是支持内容，但如果比较两种回答方式，也可以登记为实验。这样可以避免把方向配额、实验配额和支持配额重复相加。

### 3. 类型差异必须落到制作层

类型差异至少要体现在四个可检查的地方：

1. **开场任务不同**：实测从疑虑开始，治愈从生活状态开始，关系从具体准备行为开始，空间从同机位变化开始，答疑从真实问题开始，交易从当前商品信息开始。
2. **动作槽位不同**：不能所有类型都使用“主图＋慢推近＋字幕”；系统应根据 `structure_id` 检查必需动作是否出现。
3. **口播功能不同**：实测讲条件和边界，治愈讲动作与感受，关系讲行为与关系落点，空间讲前后变化，答疑先复述问题再回答，交易讲当前可购买信息。
4. **成功指标不同**：实验看变量和结果，信任看完播与收藏，答疑看问题解决率，交易看商品点击和订单贡献，不能用同一个指标评价全部类型。

### 4. 当前P1/P2主线的定位

目前的 P1/P2 样片主线主要覆盖 `test_selection`、`healing_ritual` 和部分 `transaction`，属于“商品卖点验证型短片”。它可以作为 300 条系统的第一条生产路径，但不能代表完整的六类内容系统。

因此后续批量生产要做两层模板：

- **共用底层**：事实卡、主图卖点矩阵、Seedance动作片、Doubao TTS、SUNO BGM、Remotion品牌层、QA和追溯。
- **类型模板层**：P1—P6结构、开场逻辑、必需动作、口播功能、时长节奏、CTA和评价指标。

这样既能保持品牌规范统一，又能让六类视频在购买理由、动作和观看任务上真正不同。

## 四、建议的数据对象

新增或统一以下对象：

- `ProductFactCard`
- `ClaimEvidence`
- `ContentRecipe`
- `ShotAsset`
- `MotionGenerationTask`
- `VoiceTrack`
- `MusicTrack`
- `TimelineVersion`
- `QualityGateResult`
- `ExperimentCard`
- `PublishRecord`
- `ReviewConclusion`

五张业务表仍然足够作为第一版：

1. 商品事实与准入
2. 需求与内容配方
3. 制作任务与素材
4. 实验与发布
5. 复盘与资产

系统不需要先建多个 Agent。确定性的 ID、状态、权限、预算和版本变更交给程序；内容判断、事实审核、发布和广告预算保留人工闸门。

## 五、分阶段升级顺序

### P0：先固化规则

- 统一 `visual_sellpoint_spec`
- 统一 Logo、字体、安全区和编码检查
- 固化 P1/P2 事实卡字段和 claim 边界
- 固化 3–5 秒动作片和 1.5–2.2 秒卖点镜头规则

### P1：支撑首批 10–20 条

- 主图卖点矩阵
- Seedance 任务记录与失败分类
- Remotion 四层模板
- Doubao 时间戳字幕
- SUNO BGM 与音频混音
- 五层 QA 报告

### P2：支撑 300 条

- 内容配方和控制变量系统
- 批量任务队列和重试策略
- 去重与素材疲劳检查
- 事实版本影响分析
- 实验卡和发布/投放映射
- 周度复盘与经验回写

### P3：经营闭环

- 页面、直播、短视频三处购买理由一致性检查
- 价格/库存/优惠动态刷新
- 退款调整后的内容贡献利润回写
- 独立复验和放量门槛
- 过期声明、过期素材和过期音乐自动召回

## 六、哪些由系统固化，哪些保留 Agent 判断

### 系统必须固化

- ID、状态、版本、权限、预算、任务重试
- 事实和证据绑定
- Logo、字体、字号、位置和安全区
- TTS 时间戳与字幕生成
- BGM ducking 和音频轨合成
- 编码和播放器兼容性
- 去重规则和质量门
- 成片追溯链

### Agent 可以判断

- 哪个购买理由优先
- 卖点顺序和镜头顺序
- 具体 Seedance Prompt
- 景别、角度、光线和动作设计
- 是否需要重生成
- BGM 的具体风格
- 何时使用 4 镜头或 6 镜头
- 如何形成真实差异的开场与生活情境

Agent 的判断必须写入 `decision_log` 或 `ExperimentCard`，不能只存在对话里。

## 七、最终验收标准

主干升级完成的标志不是“能一次生成 300 条”，而是：

- 可以从商品事实卡自动生成一组可审核的卖点配方。
- 每条视频都能说明它为什么存在、相对父版本改变了什么。
- 素材、口播、BGM、Logo、字幕和事实可以独立替换。
- 任何事实变化都能找到受影响的视频。
- 失败可以按原因重做，而不是盲目重生成。
- 300 条不足、取消或延期时能保留原因，不用低价值重复内容填满。
- 最终能回答：哪款商品、哪个购买理由、在什么情境下、用什么证据、以什么成本值得继续。
