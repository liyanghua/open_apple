# Editorial Gallery UI 规范

## 一、页面层级

页面只允许三层视觉层级：

1. **指挥层**：批次阶段、待处理数量、预算、当前主动作。
2. **判断层**：候选真实画面、创意摘要、质量结论、少量证据标签。
3. **证据层**：抽屉内完整视频、评分细项、五项确认、音轨、成本和失败日志。

任何字段都必须归入其中一层。provider、model、runtime、generation id 不得出现在判断层。

## 二、组件规则

### 候选卡

- 固定比例 `16:9` 媒体区；卡片整体高度由固定媒体区 + 文字区决定。
- 首屏最多一个状态结论、三个证据标签、两行摘要。
- 证据标签优先展示「差异 3/6 镜头」「开场一致」「字幕已就绪」；若有阻塞，展示「字幕待补齐」「开场需确认」或「候选差异不足」。六个变体维度固定为 `hook_type/narrative_structure/visual_grammar/pacing_profile/evidence_strategy/asset_strategy`。
- 候选差异标签必须来自 `candidate_variant_plan`/差异矩阵：至少显示「变更维度数」和「结构差异镜头数」；只改变前三秒不能显示为“差异通过”。
- 点击整个卡片进入抽屉；卡片内播放按钮和选择控件阻止事件冒泡。
- 推荐使用细实线与金黄色文字，不使用大面积金色底。
- 失败使用珊瑚色文字和浅底，保留 poster，不使用 `opacity: .4` 隐藏内容。

### 决策栏

- 同一时刻只允许一个 `.primary-action`。
- 主按钮文案必须包含对象和结果，例如「通过 4 个样片并进入评分」。
- 次要动作使用无背景文字按钮或细边框按钮。
- 决策栏不得重复展示画廊中的所有候选详情，只列出待处理对象。

### 抽屉

- 桌面宽度 520px，移动端 100vw。
- 背景使用 `--surface`，遮罩使用 `rgba(32,35,34,.28)`；不得使用模糊背景。
- 抽屉头部 sticky，底部动作 sticky，中间证据区独立滚动。
- 五项确认采用纵向 compact rows，不使用五张独立大卡片。
- 字幕状态必须显示业务结果：`字幕已就绪`、`字幕待补齐`、`已确认无字幕`；空值、`null` 和内部字段名不得直接进入 DOM。
- 播放器下方必须显示候选九阶段进度；阶段状态与质量评分分开表达。
- 「修改并重跑」先打开自动规划区，默认推荐最小安全路径；确认按钮必须显示新 revision 和预计成本。
- 重跑中的候选显示“重跑中”和当前起始阶段，不显示旧版评分为当前结果。
- 重跑期间旧版仍标记为「当前版」，保留旧评分、审批和可用预览；新版本只能在预览区或最终复核区显示为 draft。
- 重跑监控必须显示 `base → target` revision、当前阶段、进度、预计剩余时间和「本次预期变化」。
- 先显示可审阅预览再进入完整重跑；预览未通过时不得自动消耗完整成片成本。
- 技术修复若只影响一个失败阶段，修复结果直接进入最终复核，不再重复消耗完整成片生成。
- 预览或完整成片不满意时提供「保留当前版」；取消/放弃不会提升 revision，也不会清除旧版历史。
- Remotion 与 HyperFrames 都可用时，提案阶段必须同时展示适用场景和真实权衡，不能静默默认；用户确认后锁定引擎。
- 局部重跑默认沿用锁定引擎；若用户主动切换，计划区必须标记「切换，需重新确认」，并重新显示成本、预期变化与版本影响。
- 样片门未完成或质量预检未通过时，底部主动作只能是「查看问题并修复」，不得显示「进入终稿编辑室」。
- 报告新鲜度必须以文字显示：`数据完整`、`部分来源缺失`、`报告已降级` 或 `报告待刷新`；不能只换颜色或显示内部 `status`。
- 抽屉中的制作证据可显示 `report_revision`、`run_id`、provider/model/runtime 和 source refs，但判断层只能显示业务结论。

### 局部修改路径

- 用户表达修改意图，不直接选择内部 stage id。
- 系统从当前 revision 和依赖图计算最早受影响阶段，并展示会保留的阶段。
- 修改路径至少覆盖：节奏/镜头、口播/字幕、画面/素材、技术修复。
- 新版本不继承旧审批；规划期间 revision 变化时必须提示重新规划。

### 修改意图输入

- 入口按「定位 → 描述 → 复述」组织，不提供没有上下文的空白大表单。
- 定位优先使用播放器时间段、镜头标签、质量维度和失败阶段；点击后自动带入当前 revision 的锚点。
- 描述支持快捷问题类型 + 一句自然语言，推荐句式为「位置 + 问题 + 目标」。
- 计划面板必须展示「已理解」摘要；摘要至少包含定位锚点、用户目标和将受影响的阶段。
- 描述不完整时只追问一个最小澄清项；不得要求用户理解 `edit`、`scene_plan` 等内部 stage id。

### VLM 低分建议

- VLM 建议必须显示评分维度、分数、证据定位和建议动作；建议是可勾选范围，不是自动执行命令。
- 用户勾选建议后，系统可生成可编辑草稿；用户输入与 VLM 建议必须分别标记来源。
- 摘要区区分「系统草稿」与「已理解」：只有用户实际修改或确认文字后才使用「已理解」，并同时显示 `VLM 建议范围`、`用户补充范围` 和合并后的影响阶段。
- 多个低分项一起勾选时按依赖闭包并集规划重跑；若定位与文字描述不一致，确认按钮阻止提交并给出最小修正提示。
- 没有低分项时显示「未标记低分」，保留同样的手动定位和描述入口。

### 样片质量证据

- 开场证据固定显示 `00:00–00:03` 的证据帧、首段口播摘要和一致性结论；冲突时必须说明下一步，不得只显示低分颜色。
- 候选差异证据显示差异镜头数和差异类型；共享素材池不等于相同候选，但只有结构化差异才计入覆盖数。
- 结构差异、视觉相似度和报告数据完整性分开显示；“数据不完整/已降级”是状态结论，不用低分颜色伪装成质量结果。
- 效率与效果报告摘要只显示总耗时、最慢阶段、重试/缓存、成本、质量门结论、返工次数和推荐动作；provider、model、runtime、run id 进入证据层抽屉。
- 批页完成样片门并选择 1–2 个候选后，主动作改为「进入终稿编辑室（2 个候选）」；点击后分别打开选中候选当前 revision 的深链。
- 未通过、未评估或 revision 过期的候选只能查看证据，不能进入终稿编辑室。
- 差异矩阵的单元格必须同时给出 `changed_dimension_count`、`structural_shot_count`、`structural_status` 和 `visual_similarity_risk`；“结构同质化”与“视觉相似度过高”是两个独立结论。
- 缺少 `candidate_variant_plan` 时显示“差异证据缺失”，不能把未知当作通过；`hard_gate` 模式下禁用批级审批和选择，`warning` 模式下保留动作但附 warning。
- 批级审批过程显示协调状态和参与者计数；`stale`、`forbidden`、`validation_failed`、`needs_recovery` 必须降级为重新拉取/查看原因，不显示“已通过”。

### 标签

- 仅用于状态、证据和过滤，不用于装饰。
- 标签文本必须是用户能理解的业务词：`推荐`、`可选`、`需返工`、`技术失败`、`口播清晰`。
- 禁止直接显示 `status=sampled`、`evaluation_report` 等内部枚举。

## 三、间距与尺寸

```text
基础间距：4 / 8 / 12 / 16 / 24 / 32
页面左右内边距：桌面 32，平板 24，移动 16
候选画廊间距：16
决策栏宽度：300–336
媒体圆角：8
容器圆角：不超过 10
按钮最小高度：40
触控目标：44 × 44
```

页面区域用线和留白分组，不使用“卡片套卡片”。

## 四、文案规范

- 状态优先说结果：「待确认」而不是「awaiting_human」。
- 错误优先说影响和下一步：「样片尚未生成，暂时不能进入评分」而不是「sample_ref missing」。
- 批量动作必须带数量：「通过 4 个候选」而不是「全部通过」。
- 选择动作明确上限：「进入精剪（最多 2 条）」。
- 评价标签保持短语化，避免一张卡出现多段解释性文字。

## 五、动效规范

- 页面首次载入只做一次淡入和画廊错峰出现，时长 180–240ms。
- 抽屉使用 220ms `cubic-bezier(.22,.8,.25,1)` 滑入。
- 候选选择只改变边框、底部托盘和右栏数字，不做缩放或弹跳。
- 播放状态只显示轻量播放指示，不叠加持续闪烁动画。
- `prefers-reduced-motion: reduce` 时移除位移和错峰动画。

## 六、交付前检查

- [x] 真实媒体帧可见，未用抽象渐变替代内容图
- [x] 首屏能看懂当前主动作
- [x] 卡片文本没有溢出或遮挡
- [x] 抽屉打开/关闭可恢复焦点
- [x] 选择超过 2 条即时阻止
- [x] 桌面、平板、移动端均无横向滚动
- [x] 失败候选可见且说明原因
- [x] 页面不出现紫色渐变、霓虹 glow、emoji 图标或技术字段瀑布
- [x] mockup 按 `1440px`、`1024px`、`390px` 三档检查，且静态服务器命令已写入交付说明
- [x] 抽屉使用 `role=dialog`、`aria-modal`，打开后焦点进入标题，关闭后回到触发卡片
- [x] 抽屉展示九阶段进度，并能从修改意图生成最小重跑路径
- [x] mockup 动作使用 fake adapter，不连接未满足跨项目一致性契约的生产端点
- [x] 字幕空值不会渲染为 `undefined`，且缺失状态可在候选卡和抽屉中定位
- [x] 每个候选显示差异覆盖与开场一致性证据；五候选不再只靠首镜/首句区分
- [x] 样片门完成后选择 1–2 个候选才能进入终稿编辑室，入口携带当前 revision
- [x] 报告摘要显示输入 hash、新鲜度、数据完整性与推荐动作，过期/降级时写入动作会被禁用
