# 跨品类生产契约与首件验收

本升级将品类制作规则、SKU 商品事实和品牌视觉规范分开。`category_profile` 只描述商品身份核看项、可拍动作与证据映射、内容结构约束、镜头时长和品类核看说明；具体卖点和允许措辞继续由 `fact_snapshot` 决定；LOGO、字体、版式和口号继续由 `brand_profile` 决定。Seedance、Doubao TTS、Remotion 及原有生产流水线不因换品类而替换。

## 版本与绑定

2026-10-16镜头级扩展见[通用能力实施方案](superpowers/plans/2026-10-16-shot-production-generalization.md)。沙发垫新增 `config/category_profiles/sofa-cushion-v2.json`，补尺度、接触与构图承诺核看；v1保留原字节，历史审批继续绑定v1，新生产锁显式选择v2。源片按镜头／修订／用途审核，局部用途通过不替代原全貌任务或完整片审批。

新计划、内容配方、模板运行计划和单条生产记录使用 `1.1`。每份文件的 `category_profile_ref` 包含 `path`、`profile_id`、`category_id`、`version`、`artifact_sha256`。路径只允许项目内 `artifacts/` 或仓库的 `config/category_profiles/`，读取时核对内容哈希和身份。`production_record` 还须绑定带文件 SHA-256 的 `fact_snapshot_ref` 与 `brand_profile_ref`；最终审核的依赖闭包包含品类配置的实际文件字节。任一事实、品牌、品类配置或成片版本改变，旧审核不再对新版本有效。

现有毛巾 `1.0` 记录继续按原格式读取；其动作词表及证据映射已收进 [毛巾品类配置](../config/category_profiles/towel-v1.json)。旧记录不补造 `1.1` 字段或历史审批。新记录缺少品类引用时直接阻断，未知品类的证据不能回退到毛巾动作。展示类毛巾主体剪入时长维持已批准的 1.8–2.6 秒；不同内容结构要在配置中明确声明自己的范围。

## 换一个品类时的输入

1. 为明确 SKU 建立有来源、版本和审批状态的商品事实快照。所有计划使用的宣称必须引用已授权 claim ID 与允许措辞；商品页标注不当作生成画面的实测证据。
2. 为新品类建立并校验 `category_profile`：`identity_checks` 记录商品识别点，`action_visible_results` 为每个动作规定画面应出现的结果，`evidence_requirements` 为每个证据 ID 规定来源类型、可见结果与 SKU 绑定要求，`allowed_structures` 限定可用内容结构，`shot_timing` 和 `qa_checks` 规定节奏及品类核看项。映射必须完整，缺口会被配置校验拦下。可参考 [桌垫离线配置](../config/category_profiles/table-mat-v1.json)，但具体参数要按新品类重新确认。
3. 选择获批的品牌配置，登记原始商品图、处理图、实拍和生成素材的来源、SKU、使用范围、哈希及必要授权。未获得可用素材和事实时不启动付费生成。
4. 建立三个画面承诺不同的动态开头和一个可冻结主体。先审核各 3 秒预览，再拼接完整变体，验证冻结主体、接缝、口播、字幕、商品事实和视听质量，最后在审核台对具体版本验收。开头创意可以由 Agent 提案；动作是否真实、商品是否变形和卖点是否兑现必须有可审证据。
5. 只在首件通过后按内容结构分批扩量。新品类不继承毛巾的成本、通过率或审核结论。

离线桌垫首件的配置、模板和运行计划样本在 [tests/fixtures/category_profile](../tests/fixtures/category_profile)；它们验证契约和付费前拦截，不代表获批商品事实、真实素材或已经生成的视频。没有下一款 SKU 的资料前，本轮不进行付费生成或发布。

首件记录至少填写以下字段，任何待定项保持 `pending`，不能以桌垫离线样本代替：

| 字段 | 要求 |
|---|---|
| 商品与事实 | 明确 SKU、获批 `fact_snapshot` 路径及哈希、选用 claim ID 和允许措辞 |
| 配置 | 品类与品牌配置路径、版本及哈希 |
| 素材 | 每段原始或生成素材的来源、权利/使用范围、SKU 关联、哈希和可见结果 |
| 动态开头 | 三个候选分别写明 0–3 秒承诺、动作、结果、引用的证据和预览路径；必须有真实商品动作，三个承诺不能只是换字 |
| 冻结主体 | 主体成片路径及哈希、冻结起点、口播/BGM/字幕版本和接缝检查 |
| 审核 | 预览逐版反馈、完整变体的事实/技术/品类质检、最终人工审批及所审版本 |

桌垫离线示例可用“贴边对齐”“掀角展示”“表面擦拭”做三种**候选动作方向**，但这些不是已生成的开头，也不构成任何未经商品事实确认的功能承诺。

## 核验边界

`validate_campaign_bundle(..., paid=True)` 检查计划与配方的品类引用一致、SKU 和事实快照一致、所选 claim 已授权且措辞有据；未知证据 ID、错误动作及不适用结构会被阻断。`check_template_run_plan_ready` 在付费准备阶段重新核验品类路径、哈希、目标品类和素材槽位绑定。品牌预检从品类配置取镜头节奏，从品牌配置取视觉与声音收尾规则；审核台使用当前品类的核看文字。品类质检项进入必要检查，核验结果须绑定具体成片、报告和品类版本。自动检查保留真实状态，人工审批只绑定所审成片与依赖版本。

首件验收至少覆盖：缺失事实或素材、错误品类动作或证据、越界宣称、品牌配置不匹配、配置文件变更后的审批失效，以及其它品类工作台不出现毛巾专属提示。
