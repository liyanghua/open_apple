# Backlot 成片运营审核台增量设计

**状态：** 已确认，待实施
**日期：** 2026-08-19
**依赖基线：** `2026-08-15-backlot-operator-workbench-design.md`、`cinematic-fast` 生产 artifacts
**首个验收项目：** `table-mat-mix-v6`

## 1. 背景

当前“成片生成”页面只显示成片文件、基础参数和 QA 结果，运营人员只能播放或
下载，无法快速回答以下问题：

1. 为什么播放器封面是黑的，发布时应该选择哪一帧；
2. 一句完整文案跨多个镜头时，画面、口播和字幕是否仍然对齐；
3. 是否已经配置 BGM，音乐与口播的关系是否合适；
4. 结尾是否完整，品牌、产品和行动引导是否收住；
5. 前三秒是否足够吸引人，有哪些可替换方案；
6. 修改后会影响什么、需要重做多少、何时能看到新版。

本设计把该页面升级为“运营审核台”。它提供类似剪辑软件的时间线理解能力，
但不建设自由拖拽的专业非线性剪辑器。

## 2. 产品目标

1. 在一个页面完成成片播放、时间线审核、候选选择、文案微调和版本比较。
2. 用四条业务轨道解释最终视频：画面、口播、文案、BGM/SFX。
3. 文案按完整语义句展示，允许一句话跨越多个镜头。
4. 封面、前三秒、BGM 和结尾分别给出可理解的候选及选择依据。
5. 用户先暂存修改并查看影响，再批量生成一个完整新版。
6. 新版本只有通过完整 QA 后才能成为当前成片。
7. 历史项目在没有新 artifact 时仍能通过确定性投影进入该页面。

## 3. 非目标与边界

- 不提供任意轨道增删、自由拖拽、关键帧、曲线、调色节点或插件系统。
- 不在浏览器中直接调用 TTS、音乐、视频或图像 provider。
- 不把每个候选都立即渲染为一条完整成片；用户组合选择后只生成一个新版。
- 不伪造 BGM 候选。曲库为空且项目无音乐时必须显示真实空状态。
- 不允许参考视频、参考视频音频或参考视频帧进入封面、候选、时间线或成片。
- 不因页面编辑绕过 creative/sample approval、费用确认、production lock 或 QA。

## 4. 页面信息架构

桌面端采用三段式布局：

```text
+----------------------+--------------------------------+
|                      |  当前版本 / V1 V2 V3            |
|      成片播放器       |  封面候选                       |
|  poster + 时间码定位  |  前三秒候选                     |
|                      |  BGM 候选                       |
|                      |  结尾候选                       |
+----------------------+--------------------------------+
| 画面轨  [镜头 1][镜头 2][镜头 3]                       |
| 口播轨  [-----------完整语义句-----------]             |
| 文案轨  [-----------完整语义句-----------]             |
| 音乐轨  [BGM----------------][SFX]                      |
+-------------------------------------------------------+
| 暂存修改  | 查看影响  | 生成新版                         |
+-------------------------------------------------------+
```

- 中间区域：单一主播放器，显示当前所选完整版本。
- 底部区域：四轨审核时间线，与播放器播放头同步。
- 右侧区域：模块化候选决策栏，不嵌套多套完整播放器。
- 顶部版本切换：使用同一个播放器切换 V1/V2/V3，并显示该版本变更摘要。
- 移动端：播放器优先，候选栏和四轨时间线折叠为上下分区；不横向挤压文字。

## 5. 播放器与封面

### 5.1 首帧黑屏处理

播放器必须设置真实 `poster`。poster 来源优先级：

1. 用户已选择的发布封面；
2. 当前版本自动选出的清晰产品帧；
3. 当前成片第一个通过黑帧检测的有效帧。

封面是独立交付文件，用于播放器 poster 和平台发布封面，不默认插入视频时间线。
候选只能来自自有素材、当前成片或本项目生成资产。

### 5.2 播放同步

- 点击任一轨道片段，播放器跳转到该片段起点。
- 播放时播放头同步移动，当前镜头、语义句和音频片段高亮。
- 时间线缩放只提供“适应全片”和少量固定档位，不提供无限画布。
- 轨道仅用于审核和受约束编辑，不允许任意重排造成合同外时间轴。

## 6. 四轨时间线

### 6.1 画面轨

每个片段显示缩略图、运营可读镜头名、起止时间和素材来源。选中后展示：

- 该镜头在成片中的内容；
- 使用的自有素材及截取范围；
- 与参考结构的对应理由；
- 素材匹配证据；
- 裁切、速度、转场等已生效处理。

### 6.2 口播轨

按完整语义句显示口播，不按镜头硬切文字。一句话可以横跨多个画面片段。片段展示
文本摘要、起止时间、音色和状态；点击后可试听或进入行内编辑。

### 6.3 文案轨

按语义句或完整屏幕文案显示，不把一句话拆成多个无意义片段。每条文案旁提供
编辑按钮：

1. 默认显示最终文本；
2. 点击后原位变为编辑框；
3. 保存到页面草稿，不立即修改正式 artifact；
4. 默认同时更新字幕与对应口播文本；
5. 用户可显式取消“同步口播”，此时必须提示音画可能不一致；
6. 查看影响时说明是否需要重新 TTS、重排字幕、调整时长或完整重渲染。

语义句与镜头是多对多关系。时间线投影必须保存句子覆盖的镜头 ID，不复制多份
文本制造假分段。

### 6.4 BGM/SFX 轨

展示曲目名、来源、起止时间、淡入淡出、音量和 ducking 状态。没有 BGM 时显示：
“当前成片未配置背景音乐”，并说明可以从可用曲库选择；曲库为空时不展示虚假
试听项。

## 7. 候选决策栏

### 7.1 模块化候选

右侧依次显示：

- **封面：** 2-4 个清晰候选帧，显示产品可见性和文字安全区提示；
- **前三秒：** 2-3 个钩子方案，显示镜头顺序、首句、预计节奏和选择理由；
- **BGM：** 项目现有音乐和本地曲库中的可用选项，支持试听和音量建议；
- **结尾：** 2-3 个结束方式，显示最后画面、CTA、品牌/产品收束与预计时长。

每个候选必须展示它改变的内容和保留的内容，不能只显示“方案 A/B/C”。

### 7.2 候选生成时机

完整成片通过 QA 后，系统可以自动使用本地分析与现有项目素材准备候选。该过程：

- 不调用付费模型；
- 不生成新的商业资产；
- 不改变当前正式版本；
- 不读取或复用参考视频媒体内容；
- 可重复执行且结果幂等。

若某类候选无法从现有资产可靠产生，显示原因和下一步，不填充占位方案。

### 7.3 组合与生成

用户可分别选择封面、前三秒、BGM 和结尾，并编辑语义句文案。所有选择先进入
“待生成修改”清单。页面提供：

1. **暂存修改：** 保存草稿，刷新后仍在；
2. **查看影响：** 显示受影响轨道、镜头、审批、费用和预计时间；
3. **生成新版：** 原子提交 `delivery_review` 决策，随后由生产流程消费并生成一个
   完整版本。

如果影响预览包含付费调用，必须再次显示费用并等待明确确认。

## 8. 版本模型

- V1/V2/V3 是完整成片版本，不是候选模块版本。
- 一个版本包含视频、poster、字幕、音频混合、QA 和变更摘要。
- 生成中新版不得替换当前版。
- 只有 QA 全部通过后，新版才可标记为当前版。
- QA 失败时保留失败版本和原因，当前版不变。
- 用户可在同一播放器切换版本，时间线随版本一起切换。
- 最近两个版本提供业务差异，如“前三秒从痛点开场改为结果开场”“新增 BGM”
  “结尾增加 CTA”，不展示 JSON diff。

## 9. 数据合同

### 9.1 `delivery_review` artifact

新增轻量、可版本化的 `delivery_review` artifact，只保存人工审核决策，不复制完整
生产时间线。建议字段：

```json
{
  "schema_version": "1.0",
  "project_id": "table-mat-mix-v6",
  "base_render_id": "render-v1",
  "base_version_id": "v1",
  "selected_cover_id": "cover-02",
  "selected_hook_id": "hook-01",
  "selected_bgm_id": null,
  "selected_ending_id": "ending-02",
  "copy_overrides": [],
  "updated_by": "operator-id",
  "updated_at": "timestamp"
}
```

要求：

- 使用 `schemas/artifacts/delivery_review.schema.json` 校验；
- 作为 compose checkpoint 的可选 artifact，不破坏旧项目合同；
- 只通过 typed adapter 提交，不接受任意 JSON Patch；
- 每次提交创建追加式 revision；
- 生产流程消费后仍保留原始审核决策用于追踪。

`delivery_review` 是 compose 页面里的独立 mutation domain，不是 pipeline stage。提交
它不得调用会失效 `checkpoint_compose.json` 的通用 stage revision 路径，也不得改变
已认证成片指针。它通过专用提交服务写入审核决策 revision，并在现有 compose
checkpoint 保持可读的前提下触发后续生产任务。

### 9.2 成片版本与认证指针

完整成片版本使用独立于 `delivery_review` 的不可变合同：

```text
operator/delivery-versions/<version-id>/manifest.json
operator/current-delivery.json
```

- `manifest.json` 绑定视频、poster、字幕、音频混合、render report、完整 QA 结果、
  来源审核 revision 和业务变更摘要；创建后不可修改。
- `operator/current-delivery.json` 是“当前已认证成片”的唯一指针，不复用
  `operator/current-generation.json`。后者仍是控制面 generation 的事务 commit point。
- 提交 `delivery_review`、开始渲染或写入未通过 QA 的 manifest 均不得移动认证指针。
- 只有与该 version manifest 绑定的完整 QA 通过后，Project Commit Store 才能在同一
  事务中登记不可变 manifest 并原子替换 `current-delivery.json`。
- V1/V2/V3 和失败回退均以 delivery version manifests 与认证指针为权威来源。

### 9.3 动态时间线投影

四轨数据由现有正式 artifacts 动态投影：

| 轨道 | 主要来源 |
|---|---|
| 画面 | `scene_plan`、`edit_decisions`、最终 render metadata |
| 口播 | `script`、narration assets、audio timing |
| 文案 | `script`、subtitle cues、caption timing |
| BGM/SFX | `asset_manifest`、audio mix、render report |

投影失败时只降级对应轨道，并显示可行动的空态；不得因为一条轨道缺失而让整个
成片页不可用。

### 9.4 草稿与 adapter

新增 Compose/DeliveryReview adapter，允许的受约束操作为：

- 选择封面候选；
- 选择前三秒候选；
- 选择 BGM 候选及受限音量参数；
- 选择结尾候选；
- 修改现有语义句文本及“是否同步口播”；
- 清除尚未提交的某项选择。

adapter 必须拒绝媒体路径、provider/model、runtime、任意镜头时间码和未知字段。
跨范围修改继续交给 Agent 或前序阶段编辑器。

`sync_narration` 未提供或首次创建时默认 `true`。显式设为 `false` 时只修改屏幕文案/
字幕，不触发 TTS，并在草稿、影响预览和提交确认中持续显示音画可能不一致警告。

## 10. 状态与兼容

### 10.1 页面状态

成片审核台至少覆盖：

- 尚未生成成片；
- 成片生成中；
- QA 失败；
- QA 通过、候选准备中；
- 可审核；
- 有待生成修改；
- 新版本生成中；
- 新版本 QA 失败；
- 新版本已就绪。

### 10.2 历史项目兼容投影

对已有成片但没有 `delivery_review` 的项目执行幂等兼容投影：

1. 从当前 render、scene plan、字幕和音频信息构建只读投影；
2. 通过现有缩略图接口获得安全 poster；允许写可删除的媒体缓存，但不得写业务
   artifact、revision、candidate 或任何 current pointer；
3. 仅在存在真实素材时生成候选；
4. 首次人工提交时再创建正式 `delivery_review` revision；
5. 多次访问或重启不得产生重复版本。

`GET operator-state` 必须保持业务只读。候选 ID 由 base version、候选类型和媒体
provenance 内容哈希稳定派生；相同输入必须得到相同 ID。需要持久化的预计算必须由
显式候选准备任务完成，不能隐藏在 GET 请求中。

`table-mat-mix-v6` 作为首个回填和浏览器验收项目。

## 11. 安全、版权与费用

- 参考视频只提供节奏、结构、镜头功能和风格分析证据，媒体文件永不进入候选与
  成片。
- 所有媒体 URL 继续经过项目 ACL 与既有 media route，不暴露绝对路径。
- 封面和候选必须记录来源类型，但运营页面只显示业务可读来源。
- 本地候选准备不得创建 cost reservation。
- 任何需要新 TTS、音乐生成或视频生成的修改走既有费用确认与 provider 决策合同。
- 版本提交、生成、QA、设为当前版均写审计记录。

## 12. 验收标准

1. 打开 `table-mat-mix-v6` 的成片页时，播放器不再以黑屏作为默认封面。
2. 四轨时间线与播放器同步，点击轨道片段可定位。
3. 一句跨三个镜头的文案只显示为一条语义句，并关联三个镜头。
4. 每条文案可行内编辑，保存后进入草稿并能查看影响。
5. 无 BGM 时显示真实空态；有曲目时可以试听和选择。
6. 封面、前三秒、BGM、结尾候选均说明具体变化与选择理由。
7. 组合修改只在用户点击“生成新版”后进入生产流程。
8. 失败或生成中的新版不会替换当前版；QA 通过后才可切换为当前版。
9. V1/V2/V3 使用同一个播放器切换并显示变更摘要。
10. 页面和接口中没有参考视频媒体 URL，也没有把参考素材复制进项目交付目录。
11. 1440x900、1280x800 和 390x844 下无内容重叠、按钮溢出或不可达操作。
12. 历史项目无 `delivery_review` 时仍可打开，重复读取不写业务状态或产生重复数据。

## 13. 决策记录

本设计确认以下产品决策：

- 采用运营审核台，不建设自由拖拽剪辑器；
- 采用单播放器、四轨时间线、右侧模块候选栏；
- 文案按语义句展示，允许跨镜头；
- 文案编辑默认联动字幕与口播；
- 候选按封面、前三秒、BGM、结尾分别选择，再生成一个完整版本；
- 封面作为独立 poster/发布文件，不插入视频；
- 候选在成片 QA 通过后本地生成，不默认调用付费模型；
- 修改先暂存并查看影响，再批量生成新版；
- 只新增轻量 `delivery_review`，时间线继续从既有生产 artifacts 投影；
- 新版本仅在 QA 通过后成为当前版；
- 参考视频继续只用于分析，禁止进入候选与成片。
