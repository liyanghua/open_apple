# 视频质量与业务反馈评估体系 · 业务对齐稿(初版)

**日期:** 2026-08-17
**状态:** 待业务拍板(Draft for business alignment)
**用途:** 和业务对齐「一条视频怎么算成功」的初步定义。本文把技术设计浓缩成业务语言;文末「拍板清单」是需要业务给出的决定。技术细节对照 [`2026-08-16-video-quality-business-feedback-design.md`](2026-08-16-video-quality-business-feedback-design.md)。

## 1. 一个框架:四个事实,分开看,互不补偿

一条视频的「好坏」其实是四件不同的事:

1. **质量好不好** — 视频本身:能不能播、合规不合规、清晰不清晰、好不好看
2. **用户收不收** — 下单人的真实行为:直接接受、改完接受、还是放弃
3. **线上成不成** — 发布后的数据:有没有人看、看完、互动、转化
4. **不成怪谁** — 归因:表现差是视频的问题,还是投放/平台/落地页的问题

核心原则:

- 四件事**独立结算,不合成一个总分**。质量好 ≠ 线上好;线上差 ≠ 视频差。
- **硬门槛先于打分**:合规、事实、可播放性失败,任何创意高分都不能补偿。
- **一个生产订单 = 一个统计单位**:内部重试、返工、改版不重复计数。
- **数据不足不是失败**:样本不够时单独记一桶,不当成功也不当失败。

## 2. 北极星:有效视频率(Effective Video Rate)

一条视频**同时满足**以下全部条件,才算「有效」:

1. 通过所有硬门槛;
2. 用户接受并发布;
3. 线上数据达到最低样本量(或观察窗口到期);
4. 主指标达到基准;
5. 所有必备护栏不破线。

报告用**双口径**,避免「数据不足」被误读成「失败」:

```
有效视频率          = 有效订单 / 已结算订单
有效视频率(剔除数据不足) = 有效订单 / (已结算订单 - 数据不足订单)
结算覆盖率          = 已结算订单 / 全部正式订单   ← 两个率永远同屏展示
```

**语义提醒(汇报时必须按这个口径解释)**:用账户历史中位数做基准时,「有效」≈「不低于该账户近期中位水平」——成熟账户的通过率天然在 50% 上下,这不是绝对质量分,而是「和自己比有没有变差」。

## 3. 第一层:内在视频质量

### 3.1 硬门槛(一票否决)

| 类型 | 内容 |
|---|---|
| **机器可自动判** | 可播放;分辨率/比例/帧率/时长/编码正确;无黑帧、坏帧、截断、严重伪影;语音可懂、响度合规、声画同步;字幕在平台安全区内 |
| **需人工/业务确认** | 事实与数字准确;合规(版权/隐私/平台政策/品牌);人物/产品/Logo 一致性;必需元素(CTA/产品/来源标注/免责声明)齐全 |

任何一条不过 → 阻断交付,不计创意分。

### 3.2 打分维度(1–5 分,附锚点与问题标签)

| 维度 | 回答的业务问题 | 低分示例标签 |
|---|---|---|
| 信息清晰度 | 想说的价值,观众看得懂吗 | 卖点不清、无依据断言、信息缺失 |
| 开头强度 | 前几秒有理由继续看吗 | 钩子弱、起速慢、封面不符 |
| 叙事与节奏 | 注意力撑得住吗 | 重复、信息过密、冷场、结尾弱 |
| 视觉执行 | 视觉语言统一可信吗 | 角色漂移、伪影、重点不分、太通用 |
| 音频执行 | 说话自然、混音可用吗 | 发音错误、节奏问题、音乐压人声、响度 |
| 平台适配 | 适合发布平台吗 | 字幕出安全区、时长不对、手机看不清 |
| 商业表达 | 支撑想要的行动吗 | 卖点弱、CTA 晚/含糊、品牌不符 |

- 打分只用于**诊断和对比**,不能推翻硬门槛失败。
- 每次打分记录:评分者类型(自动/人工/用户)、评分表版本、分数、问题标签、证据——防止「换了评分表」导致的分数变化被误当成品质提升。

## 4. 第二层:用户接受

看下单人的**真实行为**,而不是口头评价:

- 首版接受率、最终接受率
- 平均修订轮数、从批准 brief 到可发布的时间
- 发布率、放弃率
- **拒绝必须选结构化原因**,自由文字可补充但不可替代:
  需求误解 / 策略不匹配 / 脚本弱 / 视觉风格不符 / 生成缺陷 / 语音音频问题 / 品牌合规顾虑 / 修改成本过高

## 5. 第三层:线上表现

### 5.1 两个场景

| | 场景 A:社媒内容 | 场景 B:效果投放 |
|---|---|---|
| 优化目标 | 有效观看、完播、互动、分享、涨粉 | CTA 触达、点击、归因转化、获客成本、转化价值 |
| 主指标(选一) | 归一化观看率 / 完播率 | ① 转化价值/成本 或 点击后转化率 → ② 转化率 → ③ CTA 点击率(标 proxy) |
| 护栏 | 早期留存率(低=失败)、负反馈率(高=失败) | 策略注册的负转化指标(退款/无效线索等) |

- 主指标按**验证强度**降级选择;用点击率当 proxy 时,必须显式标注,且与转化验证过的结果**分开汇报、不混基准**。

### 5.2 统一漏斗

```
曝光 → 开始播放 → 早期留存 → 深度观看 → 互动/点击 → 归因转化
```

- 原始平台数据**原样保存**;派生比率按版本化定义计算,平台 API 改动不篡改历史。
- 比率聚合用「分子之和 ÷ 分母之和」,不做按视频均值的平均。

### 5.3 观察窗口

| 窗口 | 用途 |
|---|---|
| 24 小时 | 早期诊断快照;样本不够时不能作为唯一终局 |
| 7 天 | 社媒内容默认结算窗口 |
| 30 天 | 投放转化/长尾结算窗口 |

平台×目标组合可在策略里覆盖默认值。

### 5.4 基准(按优先级降级)

1. **本账户历史**:过去 60 天同类已结算发布的中位数(≥20 条;不够扩到 90 天);
2. **同行 cohort 中位数**:平台/目标/行业/账号规模/时长/受众/付费与否全匹配,≥100 条、≥20 个账户 — **V2 才有,V1 单租户做不到**;
3. **绝对底线**:版本化冷启动兜底值。

- 结算时基准值、来源、样本量**全部冻结存档**,事后不得切换。
- 被评估视频的数据**永不进入自己的基准**(基准只取它发布之前的数据)。
- 判定规则(初版,刻意可解释):主指标过基准(高优 ≥ / 低优 ≤,相等算过)+ 必备护栏全过 + 样本量达标;缺失主指标或护栏 → 记「数据不足」,不算过也不算挂。加权总分可以在仪表盘展示,**不能用来判定有效性**。

## 6. 第四层:归因(表现差,怪谁)

| 观察到的模式 | 首要归因方向 |
|---|---|
| 曝光低 | 投放/时机/受众/选题需求 |
| 曝光正常、开始播放低 | 封面/标题/首帧/开头承诺 |
| 开头强、早期流失高 | 钩子与正文不符、节奏、承诺误导 |
| 早期留存好、中途流失 | 脚本结构、重复、信息密度 |
| 看得多、互动弱 | 情绪价值、观点、互动设计 |
| 完播好、CTA 触达低 | CTA 位置或脚本结构 |
| CTA 触达高、点击低 | 卖点、CTA 文案、受众匹配 |
| 点击高、转化低 | 落地页/价格/产品 — 通常不是视频质量 |
| 用户不发布 | brief 理解、可编辑性、创意方向、最终质量 |

- 每条诊断带置信度:**高**(与基准差异 ≥20% 且无混杂)/ **中**(5–20%)/ **低**(<5% 或有混杂,只显示为假设)。
- **低置信诊断不得直接触发策略变更**。变更走三级:单视频诊断 → 队列洞察(样本+置信达标)→ 受控实验。任何模型/模板/默认风格不得因单条视频表现好而上位。

## 7. 生产订单状态(极简)

一个订单一生只有一个当前状态,**终态不可重开**:

```
生产中 → 质量返工 → 等用户决定 → 用户要求修改 → 已接受未发布 → 发布收集中
```

终态:生产失败 / 质量失败 / 用户拒绝 / **用户取消** / 数据不足 / 有效 / 无效 / 排除

治理要点:

- 「用户取消」是**计入分母的正式结果**,不是「排除」;排除仅限观测失效(数据损坏、平台删帖),且有上限(建议 ≤5%,超限触发审计)。
- 数据不足计入分母但不计入分子 → 所以用 §2 双口径。
- 终态后重启生产 = 新订单(关联 supersedes);迟到的数据只做监控评估,不重写历史结果。

## 8. 生成生命周期(业务版)

7 步,**便宜的决策先于昂贵的生产**:

1. **目标定义** — 为什么做这条视频:平台/账号/场景 A 或 B/受众/主目标/主指标/行业/预算/约束/不可接受结果
2. **内容策略** — 哪个内容假设能达到目标(角度/承诺/钩子/证据/CTA/风险),小批量替代方案里批一个
3. **脚本与分镜** — 钩子→问题/利益→证据/价值→记忆点→CTA,每段记录业务目的与预期观测点
4. **创意样片** — 封面/首帧、前 3–8 秒、一个代表段落、配音字幕、CTA 处理;先批准再全量
5. **正式生产** — 创意锁定后生成、剪辑、合成、渲染
6. **发布接受** — 自动硬门槛 → 用户接受(直接接受/改后接受/拒绝/放弃)
7. **线上学习** — 窗口快照 → 与基准比 → 结算 + 归因

## 9. 落地节奏

- **V1(可闭环)**:结构化目标+主指标;订单分母;硬门槛+小评分表;结构化接受/拒绝;发布记录;手动/CSV 数据导入;24h/7d/30d 快照;账户历史基准+绝对底线;漏斗+四类独立结果。cohort 基准推迟到 V2。
- **V2**:平台 API 自动采集、cohort 基准服务、规则归因、模型/策略对比、告警。
- **V3**:受控实验、人做 vs 生成增量价值、按平台/目标选策略。
