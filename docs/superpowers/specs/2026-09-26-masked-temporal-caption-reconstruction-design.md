# 字幕区时序生成修复：首镜验证设计

日期：2026-09-26。项目：`table-mat-reuse-first-v1`。

状态：用户已批准升级方向；本文件中的具体模型、一次外部试验和上传范围待确认。不是素材验收，也不是全片制作授权。

## 1. 决策与边界

采用“原片为主、字幕遮挡区生成、区外原帧强制回贴”。模型输出只是修复候选，不直接作为新镜头使用。源片没有拍到的背景只能称为生成重建，不能称为找回原始像素。

已有本地配准能力通过 81 项软件测试，但 s01 实拍仅恢复 292/489,022 个掩码像素（0.0597%），旧字几乎完整残留。保留该实验和失败记录，不再沿用它作为本次主修复方法。

本次只验证 s01；不重做 s06、不批量去字、不合成全片，不变更脚本、5 组豆包 TTS、Remotion/Atelier、音乐方案、长方形桌面与柔软透明桌垫要求。新字幕仍按已批准的位置和无黑底样式，但本次去字诊断片不叠新字、不加音频，避免掩盖缺陷。

## 3. 数据流与职责

```text
已授权源片 + 固定字形掩码 + 单镜契约
      │
      ├── 原始 38 帧 RGB ────────────────────────┐
      │                                          │
      └── 首尾补帧 + 同步遮罩 → VACE 候选 81 帧    │
                                 │                │
                         帧契约/对位检查           │
                                 │                │
                        仅取回对应 38 帧           │
                                 └── 遮罩内合成 ←─┘
                                          │
                           无损主文件 + 逐帧证据 + 审核片
                                          │
                              人工审核后才考虑下一镜
```

拆成三个有限单元，不建立通用视频编辑平台：

1. **本地准备器**：复用现有输入安全、CFR、显示旋转、尺寸、片段验证；产生不可变 `repair_contract.json`、上传片段/遮罩、帧映射和哈希。无网络、无付费。
2. **registry provider 适配器**（拟名 `vace_caption_candidate`）：继承 BaseTool，仅接受批准的 fal endpoint、请求契约和预算预占；负责上传、提交、恢复同一个 request ID、下载；不决定是否改脚本/换模型/重试。
3. **本地合成与验证器**（拟名 `masked_caption_composite`）：接收原片、掩码、候选和契约；拒绝错位；仅替换允许区域，产生无损主文件和报告。不含网络调用。

代理负责阶段/审批/模型选择，Python 只负责工具和持久化。现有 `temporal_caption_repair` 保留原有“纯源像素”语义，不通过同名工具偷偷改成生成。新工具不自动加入通用 selector 的默认路由。

## 4. 首镜输入与遮罩契约

- 源片：`projects/table-mat-reuse-first-v1/inputs/reference/douyin-7670014963255151913.mp4`。
- SHA-256：`163a97e1536698d5dff1a61b075b60de7acfdf0500cde661c29664a45a8d0a61`。
- 源帧半开区间 `[0,38)`，720×1280，30/1 fps；本次不应用成片的 `[0,42)` 时长。
- 既有掩码：`analysis/assets-correction-v3/s01-caption-glyph-mask-v2.pgm`，SHA-256 `e4cdd2fa8c772889b2766ec5e3583893fd4642a921566297c600d51bbc9ba6d8`。
- 掩码 `M` 为精确字形区域，12,869/921,600 像素，约 1.3964%；bbox x222–496、y977–1026 仅用于展示，**不是允许整块编辑的矩形**。
- 首次试验不扩大 `M`。字幕位置固定，38 帧共用此掩码；送模前逐帧检查完整覆盖字及阴影。若发现覆盖不足，停止并提出有图示的掩码修订，不自行扩成条带。
- 送模遮罩、允许编辑区域和最终合成区域一致。白色 255 为待修复，黑色 0 保留；Hugging Face 的 Wan/VACE 文档已确认这一极性。fal 的具体预处理仍需适配验收，若实际语义不符，拒绝该适配，不反复付费猜测。
- 初版使用硬合成，不做跨边界羽化/调色。若出现接缝，判失败；以后要内缩羽化或扩大掩码，另作明确修订，不能边测试边扩大授权区域。

## 5. 帧映射：不能让“去字”改变节奏

fal 公开 schema 的 `num_frames` 范围为 81–241，同时提供匹配输入帧数/帧率选项；不能据此假定 38 帧输入一定被原样接受。本次统一准备 81 帧，避免隐藏的短片扩展：

- 上传帧 `j∈[0,81)` 对应源帧 `clamp(j-21,0,37)`。
- 前加 21 帧源帧 0，后加 22 帧源帧 37；遮罩同步重复，不跨入相邻镜头。
- 模型输出仅允许精确 81 帧、720×1280、30 fps；取 `[21,59)` 得到 38 帧。
- 补帧只是模型适配输入；不进入样片，不改变获批镜头时长。不用 optical-flow 插帧，不把 16 fps 视频提速成 30 fps，不缩放来掩盖输出尺寸不符。
- 建议锁定：`match_input_num_frames=true`、`num_frames=81`、`match_input_frames_per_second=true`、`frames_per_second=30`、`resolution=720p`、`aspect_ratio=9:16`；插帧数/时序降采样均为 0，auto downsample=false，preprocess=false。
- 一次候选使用 seed=20260926、30 steps、guidance=5、unipc、shift=5、acceleration=none、video_quality=maximum；禁用 prompt expansion，保留 safety checker。不提交商品图、首尾替代图，不要求改色或换材质。

这些参数是本次试验设计，不表示已调用成功；远端模型内部的重建仍可能移动桌沿。相同帧数/帧率只能验证容器契约，不能证明内容对齐。

## 6. 合成、对位及验收

对每个源帧 `S[t]` 和对应生成帧 `G[t+21]`，输出为：

`O[t,p] = G[t+21,p] if M[p] else S[t,p]`。

不使用模型生成的区外 RGB，不对整个输出统一调色。原片解码颜色参数固定并记录；主文件用 FFV1/bgr0，逐帧解码校验。MP4 是有损审核代理，不能宣称其区外像素零变化。

验收分开记录：

| 检查 | 放行条件 |
| --- | --- |
| 输入保护 | 原片/掩码/TTS 哈希未变，新目录输出、不覆盖历史 |
| 时空契约 | 候选 81 帧/30fps/720×1280，帧 PTS 连续；剔补帧后 38 帧；任何尺寸/旋转/帧数不符直接拒绝 |
| 内容对位 | 在未遮挡的桌沿/木纹邻域检查每个对应帧；自动局部匹配仅作诊断。失配/证据不足标 `alignment_unverified`，不得标自动通过；38 帧逐帧人工对照后才能消除该状态 |
| 区外保护 | 无损主文件全部 38 帧、所有 `~M` 像素与源帧 RGB 完全相等，差异像素数必须为 0 |
| 区内质量 | 100% 局部检查全部 38 帧，无可辨识旧字/阴影、无纹理涂抹、无桌沿折断/重影；只看首中尾不足以通过 |
| 时序质量 | 正常速度循环和 0.5 倍速播放无纹理闪烁/跳动/边缘游走；出现任何明显一帧异常即拒绝，不用均值分数覆盖 |
| 生产准入 | 上述数值证据 + 首镜人工明确批准；工具 `success=true` 不代表视觉通过 |

提供原片/候选/合成三列对照、局部放大、完整 38 帧 contact sheets 和正常播放审核片。自动检查不能证明背景真实；遮挡区域继续标 `generative_reconstruction`。已露出的桌垫轮廓与厚度不得被模型改写成新的商品事实。

报告分开存 `contract_passed`、`outside_mask_exact`、`alignment_status`、`visual_review_status`、`accepted_for_production=false`，不将填满掩码计为“修复成功率”。报告保留源/掩码/上传/候选/输出哈希、帧映射、参数、endpoint、request ID、模型版本（服务未提供则写 `provider_unreported`）、代码提交、时间和账单状态。

## 8. 实施范围和失败路径

继续使用 `codex/temporal-caption-repair` 独立工作区，不混入脏主线。先实现无付费的契约/合成测试及 mock provider 测试，再按批准范围实测一次；不得把测试替身生成的片段作为真实模型效果展示。

最小测试集：帧 padding/unpadding；损坏/错误极性掩码与范围保护；颜色/旋转/CFR/长度错配；候选错帧和边缘错位；区外 RGB 逐帧一致；原文件不可覆盖；无审批/无预算不能上传或提交；提交不确定时禁止重新提交；超时恢复同一 ID；provider policy rejection 原样记录、不绕过；凭据和临时 URL 日志脱敏；本地步骤资源有界。

资源边界沿用当前首镜输入限制；新增部分流式处理，最多各持有一帧源/候选/输出，不将补至 81 帧的视频堆入内存。仅允许此首镜契约，candidate 下载上限 100 MiB/120 秒，ffprobe/ffmpeg 使用现有有界子进程策略；超限清晰失败、不自动降分辨率。输出落独立 run 目录，已存在则拒绝，失败记录保留，远端失败不修改 active manifest。

软件可用但素材失败、provider 语义不满足、政策拒绝、报价变化、视觉接缝、待结算费用等必须分别报告。任何一种都不触发纯生成整镜、模糊条带、静态图或换供应商兜底。

首镜通过后再申请余下复用镜头和 s06 的下一步范围；此设计不包含后续批量实现。脚本/分镜不回滚，assets 保持未批准，edit/compose 不进入。
