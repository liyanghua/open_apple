# 生产复盘与持续迭代评估实施方案

版本：v1.0｜日期：2026-10-08｜状态：**文档方案；代码、运行时 skills 与工作台升级尚未因本次文档更新而实施**。

已确认的方向：同时评估成片与生产系统；日常改动回放固定素材，关键生成策略升级再做少量重复生成和盲评。质量与事实边界优先于降本提速。

配套文件：[制作与评估规范 V2](14_卖点视频生产与迭代评估规范_V2.md)、[迭代评估卡模板](templates/迭代评估卡.md)、[本轮实际交付说明](12_P1卖点AB样片_执行结果与审核说明.md)。

## 1. 本轮生产事实与结论

本轮对象为 P1，SKU `yb-bb-03`。用户“按照文档实施”授权了 10/11 号文档对应的样片制作；没有据此批准新成片、真实性能结论或后续批量。

| 环节 | 实际执行 | 已验证与局限 |
|---|---|---|
| 商品事实 | 对照事实卡与自有商家主图，把银离子、10A、防臭、吸水、纯棉、多色映射到文案 | 资料来源可追溯；10A 等仍为商家宣称，缺少独立实测不能升级为检测结论 |
| 开头 | A：防臭问题＋浴室取巾；B：吸水诉求＋俯拍湿手接触毛巾 | 两种完整开头方案；文案、动作、构图同时变化，不是单词或单动作的单变量实验 |
| 参考输入 | 自有商品图负责外观，参考片抽帧负责动作/构图 | 不把竞品参考当自有 SKU，也不将参考片直接剪入最终时间轴 |
| 动态素材 | Seedance 2.5 新生成 6 段约 4.04 秒视频；另复用 2 段既有素材 | 真正动态生成；任务成功不等于商品、手部和动作均合格 |
| 声音 | 两个钩子分别 TTS；正文只生成一次；两版共用已批准 SUNO B 音乐 | 共用正文混音前 PCM 一致；关键名词和品牌句仍有独立 ASR 差异 |
| 剪辑与合成 | 每条七镜头、16.1 秒；正文镜头约 1.8–2.57 秒；5 帧转场；Remotion 品牌组件 | 有场景、机位与动作变化；连续动作、商品一致性仍需独立核验 |
| 输出 | 两条完整片、两条 3 秒节选，1080×1920 / 30fps / H.264 / AAC | 新素材原生 720×1280；另有方形旧素材裁切，不能称原生 1080p 生成 |
| 记录与审核 | 成片、props、回执、质量证据、费用与审核台索引已关联 | 历史前置 checkpoint 缺口保留；正式冻结与混音合同未闭环，主线生命周期尚未完整通过 |

实际质量记录：A、B 各 **8 项 pass、3 项 fail、9 项 not_run、0 项 error**。三项失败为口播内容、字幕对应、slogan；保留原始 ASR，不能先验断定全是识别错误。这个计数不是质量百分比，也不能用通过项数量抵消关键失败。

视觉评估给 A/B 的钩子清晰度分别为 8/7 分，但没有验证声音，未绑定完整放行评分政策，没有真实观看结果。现阶段结论为：**本轮制作路线可执行，画面表达发生了实质变化；效果优劣证据不足，未获完整生产认证。**

### 成本与时间的可信口径

- 六次成功视频任务共 523,800 completion tokens；沿用本轮目录估算约 **36.666 元**，实付待核实。
- 两次初始 DNS 失败经远端无任务查询确认后才恢复提交；这不同于创意失败重生成。所有尝试和恢复证据保留。
- 本数字不含完整的 TTS、评估、Agent、音乐、渲染、人工与摊销。成功但淘汰的素材也必须进入成本。
- 机器执行、排队、Agent 主动工作、人工等待和返工时间分开。文件创建时间差不等于 Agent 工时；未测量留空，不填零。
- 当前尚无本轮最终验收的合格作品，不能把生成估算简单除以两条片，称作“每条合格成片完整成本”。

## 2. 固化边界

代码执行可重复验证的约束；skills 描述制作和判断方法；workflow 决定顺序、输入输出与阶段门；Agent 负责具体表达与有依据的取舍。

| 环节 | 固化成代码 | 固化成 skills | 固化成 workflow | Agent 创作与判断 |
|---|---|---|---|---|
| 事实 | SKU、来源类别、版本、哈希和引用检查 | 卖点拆分、声明与实测的区分 | 先核事实，再批准措辞 | 选本片重点，转成用户语言 |
| 素材 | 原始/处理/输出关系、参考用途、区间使用记录 | 商品完整性、合适参考图、动作评审 | 先检索，再补缺口，合格后入池 | 选择构图、场景、机位与组合 |
| 生成 | 参数 dry-run、预算、幂等、任务恢复、usage 与探测 | 提示词结构、失败分类、最小返工 | 提交→查询→下载→检查→入池 | 手势、动作幅度、环境、运镜 |
| 品牌 | 字体文件、LOGO、几何布局、下划线、安全区 | 复杂背景可读性处理 | 预检→实际渲染测量→画面复核 | 提炼关键词、在规范内选择留白 |
| 声音 | 实际时长、词时间、尾音余量、共享正文、混音回执 | 重音、停顿、清晰度、定点试听 | 测 TTS→排时→混音→独立核验 | 文案、语气、音乐切入点 |
| 剪辑 | 时间轴、转场、源片余量、编码、依赖失效 | 镜头层次、信息推进、接缝处理 | 冻结共同正文后派生开头变体 | 排列镜头、选择剪切点 |
| 检查 | 适用性、真实状态、证据绑定、检查重跑范围 | 动作/商品审查、返工优先级 | 机器检查与内容核验完成后提交最终审核 | 解释问题及最小修正方案 |
| 迭代 | 版本差异、比较条件、指标与报告 | 盲评、证据强度、取舍说明 | 预登记→评估→采纳→晋升基线 | 提出假设、解释选择 |

### 本轮 Agent 临场发挥的具体内容

- 选择“怕有味”和“洗完手”作为两个入口，以及浴室、窗边、擦拭、织纹的组合。
- 根据素材实际呈现，选择轻提、翻角、按压/滑动的可用区间，而不是只读提示词就认定完整展开或回弹已发生。
- 根据实际口播，把约 18 秒时间草案落到 16.1 秒，调整开头语速、镜头分配和音乐入点。
- 对颜色展示的可见区域、文字与接触部位的关系做具体构图判断。

这些选择应保留理由，不变成每条必用的七镜头模板。若实际动作不满足已批准的承诺，保留原要求及执行差异；不能事后降低标准、改提示词记录来把失败变成通过。

### 应优先消除的人工整理工作

1. 工具自动输出项目相对路径、输入/输出哈希和统一执行回执，原始 provider 回执保持不可变。
2. 生成前建立生产记录和任务身份，随后追加结果；不在成片后从多个文件反向拼装完整记录。
3. canonical props 在渲染前定版；DOM、ASR、judge 自动绑定同一媒体及 props，避免人工修复关联。
4. 原始混音输入、参数、执行回执、后处理和最终音轨关联完整，不能用“听起来相同”替代来源证据。
5. 缺前置流程时尽早报告当前可执行范围；旧记录采用显式历史导入，不能绕过门禁或补造完成阶段。

## 3. 评估体系及比较方法

### 四张成绩单，分开作结论

| 成绩单 | 回答的问题 | 必须保留的证据 |
|---|---|---|
| 生产质量 | 是否正确、可交付，有无新增关键缺陷 | 技术测量、事实依据、商品/动作核验、声音、审批绑定 |
| 创意表现 | 是否更清楚、更有观看理由 | 六维评价、盲评偏好、问题与优秀片段时间点 |
| 系统效率 | 是否更稳、更少人工、更少消耗 | 全部尝试、首次合格率、费用、各类耗时、返工原因 |
| 经营效果 | 发布后观看与交易表现如何 | 原始导出、分母、受众、曝光分配、窗口和限制 |

原有百分制和 video_judge 评分保留各自版本、量纲和用途。新的六维人工量表不直接折算成原百分制；任何综合排序分都不能覆盖关键缺陷。

### 三种迭代，分别锁定变量

| 比较类型 | 固定项 | 变更项 | 结论边界 |
|---|---|---|---|
| 成片迭代 | 同一 brief、SKU、受众及预登记不变项 | 开头、镜头、口播等明确因素 | 多因素一起变化只能比较方案，不能归因到单一因素 |
| 系统迭代 | 同一任务集、输入资产、审核与评价规则 | 代码、skill、workflow 或生成策略 | 不能只展示新系统最好的一次，忽略失败和淘汰 |
| 评估器迭代 | 同一批媒体及冻结人工标签 | Judge 模型、提示词、评分规则 | 分数涨不等于成片变好；比较漏检、误拒及人工一致性 |

每轮先填[迭代评估卡](templates/迭代评估卡.md)，再执行。基线必须绑定具体版本；尚未验收的当前 A/B 只能进入诊断集，不能自动升级成优秀基准。

报告统一输出 **改善 / 退化 / 持平 / 有取舍 / 证据不足**，并附证据强度。硬性缺陷已证实时可以明确报告退化；其他维度缺证据时仍单独显示未知，不靠总分冲掉已知问题。具体判定遵循 14 号规范。

### 日常回放与关键升级实跑

- 日常：固定输入与素材回放；必要时本地重渲染。检查品牌、时间轴、检查状态、审批失效、重复提交和记账，不触发付费生成。
- 关键生成升级：默认选择 3 个代表任务，旧、新各运行 3 次，共 18 次任务执行。任务是一个镜头还是完整单条、每次调用数与费用必须在卡片中明确，不能把 18 次任务误写成 18 次 API 调用。
- 重复运行的预算单列，先评估再按实际授权执行；本文件不是付费授权。历史最好结果不能替代旧版本的同期重复执行。
- 同任务匹配比较，平衡执行顺序，记录模型实际标识、参数及种子支持情况；相同种子不保证外部服务完全确定性。
- 所有失败、淘汰、人工干预都进入报告。只比较选中的成片时，同时报告候选选取成本和失败率。
- 3×3 是方向性诊断，不保证统计证明；不要把同一个 brief 的重复结果视为多个独立创意样本。

### 首版固定评估集

首版目标为 12 例，每类 3 例，仅覆盖已验证展示类任务。实际可用样本不足时记录缺口，不用未验收结果冒充 Gold。

| 类别 | 入选要求 | 用途 |
|---|---|---|
| Gold | 已验收且具体版本、必要证据可核验 | 保持合格表现 |
| Silver | 没有关键缺陷，但存在明确可改善点 | 测试排序与改进敏感性 |
| Bad | 已确认重叠、闪烁、尾音截断等缺陷 | 测试问题定位 |
| Hard Negative | 外观好看但换款、假实测或主体未执行动作 | 测试关键缺陷误放 |

合成缺陷样本必须标为测试衍生物并保留父媒体，不进入商品素材池和 300 条计数。按商品/模板/母片同源组划分调参与检验集，避免同一片改字幕后同时出现在两边。

现有 Judge 校准门槛按项目协议执行：完整必评维度每维至少 100 个样本起步、双人独立标注与冲突仲裁、kappa 起步门槛 0.6，并检查关键误放/误拒、分维统计与置信区间。12 例用于冒烟和回归，不能据此声称完成 Judge 校准；未校准继续作为建议。

## 4. 工作流、接口与工作台升级

```mermaid
flowchart LR
    A[固定基线和改进假设] --> B[预登记比较条件与预算]
    B --> C[回放或授权实跑]
    C --> D[质量检查与失败定位]
    D --> E[盲评与成本效率比较]
    E --> F[五类结论和证据强度]
    F --> G[人工采纳具体版本]
    G --> H[晋升基线并保留历史]
```

### 复用已有能力

| 现有能力 | 保留用途 | 本次规划的补充 |
|---|---|---|
| production_quality / production_measurements | 实际质量证据与绑定 | 统一适用性、可信回执、明确缺项与重跑范围 |
| change_evaluation | 判断修改影响和渲染路线 | 影响范围输入评估计划；它本身不判断作品优劣 |
| ReplayHarness / gold_set | 固定样本回放、分组与校准 | 制作类基准集、版本比较和全部尝试汇总 |
| ReviewService / DeliveryVersionService | 版本审批及交付门禁 | 展示与基线的差异，采纳与正式批准分开 |
| opening_results | 经营结果导入及可比性检查 | 与迭代报告关联；现有兼容性检查不冒充因果推断 |
| campaign panorama / events / cost ledger | 生产总览、时间与费用 | 区分缓存回放、重新生成、等待与主动工作 |

### 最小新增记录（设计合同，尚未实现）

**iteration_plan：**迭代 ID、比较类型、brief/SKU/结构、基线与候选引用、代码/skill/workflow/模型/评估器版本、变更与冻结项、主指标、改善与等效范围、质量底线、评估集/重复/顺序、证据与预算要求。

**iteration_report：**计划引用、实际版本、完整尝试清单、比较条件核验、逐项结果、时间点证据、盲评来源、费用与耗时、失败/缺失项、判定、证据强度、限制及人工采纳。基线晋升通过现有版本审批完成，不以一个 `improved` 标签直接放行。

这两类记录关联既有 production_record 和 evaluation_report，不再建立平行生产状态表。文档模板先用于人工登记；后续实现时注册 schema、持久化与只读投影，具体线上 API 路径依现有路由风格接入。

审核台在现有页面增加“与基线比较”：旧/新同步播放、前三秒/完整片切换、只听声音、变化项、缺陷时间点、指标差异、费用与未知项。盲评状态隐藏版本名、模型名、旧分数和推荐结论；完成标注后再揭示。

## 5. 分阶段实施与完成标准

| 阶段 | 工作 | 完成标准 |
|---|---|---|
| D0 文档 | 本轮复盘、规范 V2、评估卡与入口索引 | 状态准确、规则不冲突、旧审批快照保留；本次交付仅到此层 |
| D1 可信记录 | 统一工具回执、渲染前 canonical 绑定、检查适用性、恢复与记账 | 固定验收场景通过；未知项不伪装成零或通过 |
| D2 制作方法 | 更新现有阶段 skills 与阶段交接清单 | 每阶段可从明确输入开始，输出和返工路径可追溯；不新建包办创意的总控脚本 |
| D3 迭代评估 | 记录 schema、回放接入、基准集、盲评与工作台对比 | 能识别已知退化、条件不一致与证据不足，报告绑定版本 |
| D4 校准扩展 | 关键生成升级实跑、Judge 校准、真实经营结果回流 | 按类型建立结论范围；新结构先过首件，预算另行登记 |

后续代码升级在独立研发分支验证后接入生产。当前工作区已有其他改动，本次文档更新不对其作任何实现完成或测试通过声明。

### 必须覆盖的验收

1. 字体缺失、字幕重叠、尾句截断、转场闪烁能发现并定位；缺音频输入时不能认证声音。
2. 摄影机推拉静态图不算主体动作；错误 SKU、颜色和假实测不能被高审美分掩盖。
3. ASR 与人工试听独立留存；必要项缺失不显示全通过；不适用必须有可核验的理由。
4. 开头变更导致正文/音乐变化时，对照失效；受控单变量不被普通三维差异规则误杀。
5. Judge 换版涨分不被解释为成片改善；缺基线、统计不充分不判持平。
6. 超时先查询，不重复付费；淘汰成本计入；实际结算和人工工时未知保留空值。
7. 依赖变化使旧批准失效；有记录缺口时不能补造完成阶段；未验收样片不能晋升基线或抵扣 300 条。
8. 日常回归不调用付费生成；关键升级实跑遵守独立预算；只更新文档不会触发生产或发布。

## 6. 原 300 条计划的关系

保持原三商品配额、四周排期、240 实验＋60 支持及人工/AI 路径安排。本轮 P1/P2 是验证试点，不能替代原商品或自动抵扣数量。展示类当前节奏不得直接推广到实测、微故事、仪式与轻喜剧；这些类型使用独立 recipe、证据要求和评估集。

本文件截至本次更新仍没有新增线上经营结果。完成制作、生产验收、判为创意改善与验证经营效果，分别登记。
