# 双产品批量视频生产执行计划

版本：V1.0｜日期：2026-09-20｜状态：批量生产计划已建立，等待素材入池与创意锁定

## 1. 生产目标

本批以两个已读取天猫页面的商品为独立生产单元：

- **P1**：商品ID `1060430166297`，货号 `yb-bb-03`，页面标题含“银离子抗菌”，页面参数标注“加厚款”。
- **P2**：商品ID `1072643655403`，货号 `yb-bb-12`，页面标题含“长绒棉”，页面参数标注“标准款”。

首批生产 **60条审核去重成片**：P1 30条、P2 30条，4周完成，每周15条。另做P1、P2各1条10—15秒准入样片，样片不计入60条。

成片目标是验证“真实商品证据 + 生活场景 + 页面承接”的可复制生产线，不能把60条解释成60个独立商品结论，也不能在没有同条件实测时宣布P1或P2更好。

## 2. 主线架构与批根

### 2.1 Pipeline

采用 OpenMontage 的 `cinematic-fast` 主线，模式为 `source_led_template`：

`Research → Proposal → Script → Scene Plan → Assets/Creative Lock → Sample → Edit → Compose → Publish`

商品主体优先使用真实商品照片、视频和实拍动作。AI只处理字幕、版式、节奏、图文说明和不承载商品事实的氛围层；不得生成或改写商品颜色、纹理、Logo、标签、包装、规格、检测结果、价格和库存。

### 2.2 批根和事实隔离

建议批根：`playboy-towel-p1p2-v1-20260920`。

每款商品单独建立：

```text
projects/playboy-towel-p1-v1/
projects/playboy-towel-p2-v1/
```

两款商品共享模板结构和字幕设计，但不共享 `product_facts`、商品素材、声明证据、SKU时间码或价格快照。每条交付绑定：

`product_id → content_slot_id → content_version_id → fact_version → asset/timecode → delivery_version → publication_id`

## 3. 60条内容矩阵

两款各使用同一配额，但卖点和画面必须读取各自事实卡。

| 内容组 | 每款数量 | 生产重点 |
|---|---:|---|
| A 实物与选购 | 12 | 全貌、颜色、织纹、边缘、标签、展开、折叠、挂放、页面选项 |
| B 生活场景 | 8 | 洗手后、洗澡后、睡前、来客、家庭分区、收纳等真实动作 |
| C 疑问与承接 | 6 | 页面参数、评论疑问、价格/库存读取、规格选择和商品页动作 |
| D 复验与路径比较 | 4 | 同场景复验、选购方法、制作路径和结构迁移，不做无证据优劣结论 |

## 4. 四周排产

| 周次 | P1 | P2 | 目标 |
|---|---:|---:|---|
| W0准入 | 1条样片 | 1条样片 | 素材、事实、授权、声音和字幕门 |
| W1 | 8条 | 7条 | A组实物证据 + B组基础场景 |
| W2 | 7条 | 8条 | B组生活场景 + C组高频疑问 |
| W3 | 8条 | 7条 | A/C组变量复验，发布前价格快照 |
| W4 | 7条 | 8条 | D组路径比较、补缺和最终复盘 |
| 合计 | 30条 | 30条 | 60条审核去重成片 |

每周只改变一个主要变量：开场动作、字幕密度、场景入口、CTA或剪辑节奏。商品画面、事实版本和SKU不能同时变化。

## 5. 单条视频默认规格

- 竖屏 `9:16`，建议输出 `1080×1920`，20—30秒；商品细节短片可压缩到15—20秒。
- 前1.5秒出现商品或明确生活触发；前3秒完成观看理由。
- 约70%画面为真实商品/真实动作，约20%为字幕与图形，最多约10%为不承载商品事实的氛围辅助。
- CTA只使用“查看规格、查看颜色/组合、进入商品页、评论区提问”等已核验动作。
- 动态价格、库存、优惠和发货时效只进入发布前版本；过期快照自动失效。

## 6. 批量生产阶段与门禁

### W0：事实和素材入池

1. P1、P2分别保存页面快照、商品主图、选中SKU图、详情图和页面短视频信息。
2. 采集实物：平铺、手持、织纹、边缘、标签、颜色、展开、折叠、挂放、擦拭和收纳。
3. 建立 `product_facts.json`、`media_index.json`、`source_media_review.json`，每条声明绑定证据和素材时间码。
4. 记录商品、Logo、人物、声音、音乐和场景授权；缺证据的声明降级为“页面宣称”或删除。

### Research / Proposal

输出研究摘要、素材索引、模板批、三种差异化方向和 `creative_control_plan`。方向建议：

1. **证据先行**：先展示商品与参数，再进入生活动作。
2. **场景先行**：先展示洗手台或浴室触发，再给出规格选择。
3. **疑问先行**：从“页面写的卖点怎么核验”切入，减少夸大表达。

### Script / Scene Plan

按30个槽位生成每款独立脚本，所有口播、字幕和画面都绑定 `claim_id`、`evidence_id`、`asset_id`。场景计划必须写清首帧、字幕安全区、商品出镜时间码和平台裁切。

### Assets / Creative Lock

只准备经过事实门的商品素材、统一字幕样式、CTA尾卡和音频规范。这里是批量付费资产前的人工锁定点；未通过锁定，不调用视频生成或付费音频服务。

### Sample

P1、P2各渲染一条10—15秒样片，检查：商品身份、字幕可读性、口播与画面对齐、首帧钩子、声音、裁切和事实边界。样片通过后才释放对应商品的15条周批。

### Edit / Compose / Publish

通过样片的批次再进行批量剪辑、渲染、技术质检和商品事实质检。每条输出独立文件和元数据，不直接自动上传平台；发布需要单独的外部平台授权。

## 7. 运行时与成本决策

批量模板模式推荐优先使用 **Remotion + FFmpeg后期**：字幕、版式和批量复用稳定，商品主体仍由真实素材承载。若机器可用 HyperFrames，将在 Proposal 阶段同时展示其适配性和代价；按照主线规则，不能静默锁定运行时。

视频生成API只用于非事实的氛围补位，默认不作为商品主体证明链路。任何具体 provider、model、音频供应商、预算和批量调用都在 `decision_log` 中记录，并在 Creative Lock 前获得确认。

## 8. 交付与复盘

每周输出：成片文件、脚本、事实版本、素材时间码、QA结果、平台文案和成本记录。复盘指标分为：

- 内容：3秒留存、完播率、评论问题、商品点击；
- 经营：加购、订单、退款和售后疑问；
- 生产：人工工时、工具费用、等待时间、返工次数、素材复用率和事实修正次数。

只有同一时间窗、同一口径、同一事实版本下的数据，才用于调整下一周配方；不以单条播放量宣布商品赢家。

## 10. 单条视频质量评估

单条视频先过硬门，再做100分评分。硬门不过，分数再高也不能进入发布候选。

### 10.1 五层硬门

1. **商品事实门**：商品ID、货号、颜色/组合、画面和字幕属于同一产品；没有P1/P2串素材；价格、库存、优惠只使用当前快照；页面宣称没有被写成检测结论。
2. **证据门**：每个功能性表达都有页面字段、实物画面、检测材料或评论来源；没有证据的“抗菌、超强吸水、不掉毛、防臭、触肤即干”等词降级为“页面标注”或删除。
3. **叙事门**：前1.5秒出现商品或明确生活触发，前3秒给出观看理由；全片只有一个主命题，动作、字幕、口播和CTA指向同一个结果。
4. **技术门**：分辨率、帧率、时长、音频、字幕安全区、编码、黑帧、冻结帧和首尾完整；不允许字幕溢出、口播与画面错位或商品变形。
5. **发布门**：商品页链接、CTA、平台文案和事实版本对应；没有过期价格或“库存告急”等未经快照支持的话术。

### 10.2 评分表

| 维度 | 分值 | 通过标准 |
|---|---:|---|
| 商品真实与证据 | 30 | 身份100%正确，声明逐条有来源，实物动作可读 |
| 画面与剪辑 | 25 | 首帧有信息，镜头有目的，动作连续，商品主体稳定 |
| 叙事与表达 | 20 | 一个主命题，节奏清楚，字幕/口播/画面一致 |
| 技术质量 | 15 | `final_qa`、`technical_validator(scope=final)`通过，无致命项 |
| 承接与转化 | 10 | CTA具体可执行，与当前商品页和SKU一致 |
| **合计** | **100** | **≥85且无硬门失败才进入发布候选** |

评分处理：85—100分为通过，75—84分回到Edit修订，低于75分退回Script或Scene Plan。商品事实、合规或技术致命错误直接判失败，不用平均分掩盖。

### 10.3 人工五问

每条样片和成片都由人工回答：

- 3秒后，观众能说出这是哪款商品吗？
- 观众看到的商品是否就是该SKU的真实样子？
- 这条视频只解决了一个购买疑问吗？
- 每个强卖点是否能在画面或资料中找到证据？
- 看完后，观众是否知道下一步该查看什么？

`final_qa`、`technical_validator`和`video_judge`负责自动/辅助检查；自动评分不能替代商品身份和声明边界的人审。

## 11. 批量差异性控制

差异性在脚本和Scene Plan阶段锁定，不能等成片重复后只换字幕或颜色补救。每条视频记录六维内容指纹：

`hook_type + narrative_structure + visual_grammar + pacing_profile + evidence_strategy + asset_strategy`

### 11.1 六个差异轴

| 轴 | 可选值示例 | 约束 |
|---|---|---|
| Hook | 结果先行、问题先行、评论先行、生活触发、选购清单 | 同一商品首3秒不得连续复用同一Hook |
| 结构 | 场景→商品、商品→证据、疑问→回答、参数→选择、动作→CTA | 同一结构最多占单款30条的40% |
| 视觉语法 | 微距、俯拍、手持POV、侧逆光、浴室中景、颜色平铺 | 连续两条不使用相同首帧语法 |
| 节奏 | 慢揭示、标准三段、快切、留白、ASMR动作 | 连续三条不能同节奏 |
| 证据策略 | 实物动作、页面字段、评论摘录、规格清单、同条件复验 | 没有证据的策略不入池 |
| 素材策略 | 细节先行、生活场景先行、人物手部、空间变化、组合装选择 | 同一素材不能反复承担同一叙事角色 |

### 11.2 入池规则

- 每条内容至少与上一条在六维中改变3项；只换开场、字幕或BGM不算差异。
- 同一 `hook_type + narrative_structure + visual_grammar` 组合，在单款30条中最多出现2次。
- 同一素材作为首镜最多2次；同一首帧画面不得连续出现。
- 每周15条至少覆盖4种Hook、3种结构、4种视觉语法、3种节奏。
- A/B/C/D四组配额保持不变，但每组内部也要做指纹去重。
- P1和P2可以共用“浴室/洗手台”生活框架，但商品镜头、证据、字幕和CTA必须分别绑定事实版本。

### 11.3 自动与人工复核

入池前对脚本文本做语义相似度检查，对Scene Plan做镜头/首帧/素材ID重复检查；成片后再做画面感知指纹和前3秒并排抽检。参考以下阈值：

- 脚本语义相似度 ≥0.85：退回改写主命题或叙事结构；
- 前3秒画面感知相似度 ≥0.90：退回更换首帧、动作或机位；
- 同一批次超过20%的视频共享同一首镜素材：暂停该批，重做开场分配；
- `slideshow_risk` 达到 `revise` 或 `fail`：先改Scene Plan，再进入Compose；
- 任何两条视频被人审判定为“只换字幕/颜色”：只保留一条，其余退回重做。

差异检查结果写入 `batch_plan.json` 和每周复盘，不允许用“总条数达标”替代差异性验收。
