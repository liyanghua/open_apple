# 双产品批量生产实施与主线升级方案

版本：V1.0｜日期：2026-09-20｜适用批次：P1/P2首批60条

本文件把双产品60条试点从“内容计划”推进到可执行的生产项目，并明确当前 `source_led/template` 主线需要补上的能力。目标是先跑通一条可审计、可恢复、可去重的生产波次，再扩展到300条。

## 1. 执行结论

首批采用：

```text
飞书业务输入
  → P1/P2事实与授权快照
  → cinematic-fast / source_led_template
  → 60条槽位与差异矩阵
  → P1/P2各1条样片
  → 每周15条生产波次
  → 事实/技术/人工质量门
  → 本地交付包与发布登记
  → 24小时/7天/30天复盘
```

商品主体使用真实商品素材。AI只参与字幕、图文、剪辑变体和不承载商品事实的辅助背景；商品颜色、纹理、Logo、包装、规格、检测结果、价格和库存不由模型补造。

首批不是一次性渲染60条，而是四个可暂停、可恢复的15条波次。任何一款商品事实、授权或素材被阻断，只暂停对应SKU，不污染另一款的历史结果。

## 2. 批量生产实施计划

### 2.0 飞书事实卡是否必须

需要。浏览器读取结果属于**页面快照/候选事实**，可以初始化P1/P2的 `product_facts.json`，但不能单独作为最终业务事实来源。生产和发布前，飞书商品事实表需要分别确认两款商品；P1、P2不能共用一张事实卡。

飞书至少需要确认：

- 商品ID、货号、商品标题和唯一主SKU；
- 颜色/组合、材质、棉含量、厚度等级、尺寸/克重（页面未提供的字段明确标记未知）；
- 可公开使用的商品页声明、检测报告或材料证据；
- 页面主图、选中SKU图、详情图和实物素材的权利范围；
- 价格、优惠、库存和发货信息的更新时间与有效期；
- 允许使用的措辞、禁止使用的功效词，以及对应的 `claim_id`/`evidence_id`。

当前浏览器抓取的数据已经写入P1/P2机器可读事实卡，但状态仍应标记为 `page_capture_pending_business_confirmation`。飞书确认后，生成新的事实版本和hash，只有新版本才能进入正式批量生产。价格、库存、优惠和发货时效即使已在飞书确认，也要在发布前再次刷新。

如果飞书表尚未准备好，可以先进行素材整理、脚本草稿、差异矩阵和非付费样片准备；不能把页面快照直接当成最终发布事实，也不能用未确认的事实调用付费生成。

### 阶段0：项目初始化与责任确认

**目标：** 建立项目边界，不开始付费生成。

**工作：**

1. 创建campaign：`playboy-towel-p1p2-v1-20260920`。
2. 创建P1、P2独立批根和事实版本：`P1_fact_v1`、`P2_fact_v1`。
3. 确认商品负责人、内容负责人、生产负责人、渠道负责人和数据负责人。
4. 确认首发平台、视频比例、时长、字幕语言、声音方案和预算上限。
5. 把60个槽位导入批次清单，状态设为`planned`。

**输出：** `campaign_plan`、`batch_plan.json`、P1/P2 `product_facts.json`、责任矩阵。

**放行条件：** 两款商品ID、货号、事实版本和责任人齐全；缺失字段只允许进入待补资料清单。

### 阶段1：W0素材与证据准入

**目标：** 让每个可生产槽位都有合法、可追溯的画面来源。

**P1、P2分别采集：**

- 平铺全貌、手持、颜色/组合、织纹微距、边缘、标签和包装；
- 展开、折叠、挂放、洗手后擦干、收纳和空间变化；
- 页面参数截图或快照、页面短视频信息、评论摘录；
- 检测报告、材质证明、授权和可发布范围；
- 原片时间码、拍摄日期、拍摄人、SKU、权利和可用用途。

**输出：** `media_index`、`source_media_review`、`source_semantic_index`、`reference_source_matrix`、素材授权记录。

**放行条件：** 商品证据镜头能回到对应SKU；无证据的强功效词只能保留为“页面宣称”，不能进入肯定式口播。

### 阶段2：批次创意锁与脚本锁

为每款商品先建立5种可复用方向，再从中选择当周结构：

| 方向 | 叙事骨架 | 视觉差异 |
|---|---|---|
| 结果先行 | 结果→证据→CTA | 先看动作结果，再补商品 |
| 问题先行 | 痛点→选择→商品 | 先看生活场景，再进入SKU |
| 证据先行 | 页面字段/实物→解释 | 微距、标签、清单和验证动作 |
| 高密度快剪 | 多个小信息点→选择 | 3—5个短动作，信息密度高 |
| 产品质感 | 材质/光线→生活动作 | 慢揭示、留白、细节特写 |

每个槽位必须锁定：主命题、Hook、叙事结构、素材ID、时间码、事实引用、字幕、口播、CTA和差异指纹。脚本锁定后，不得在素材阶段静默改写主命题。

**输出：** `proposal_packet`、`creative_control_plan`、`hook_plan`、`script`、`decision_log`、`differentiation_plan`。

**放行条件：** 每条脚本与上一条至少改变3个差异维度；同一开场不连续复用；P1/P2不共享商品事实引用。

### 阶段3：样片与Creative Lock

P1、P2各选一条代表性样片，建议：

- P1：加厚款、双面毛圈、颜色选择或生活动作；避免把银离子抗菌直接说成检测结论。
- P2：长绒棉页面字段、标准款、颜色组合或页面SKU文案；“触肤即干/超强吸水”只按页面选项文案呈现。

样片需要通过：商品身份、画面连续、字幕安全区、口播对齐、首3秒钩子、声音、裁切、事实边界和差异性检查。

**Creative Lock锁定：**

- 模板包与差异指纹；
- 视频比例、时长、字幕风格和CTA；
- TTS、BGM、混音和音量；
- Remotion/HyperFrames/FFmpeg运行时选择；
- 单条估算成本、批次预算和最大并发；
- 允许生成的辅助资产范围。

**放行条件：** 样片通过人工审核，且没有未解决的商品事实硬错误。付费生成调用必须在此之后进行。

### 阶段4：四周批量生产

| 周次 | P1 | P2 | 生产重点 | 复盘动作 |
|---|---:|---:|---|---|
| W1 | 8 | 7 | A组实物与选购、B组基础生活场景 | 检查素材覆盖与首3秒留存 |
| W2 | 7 | 8 | B组生活场景、C组高频疑问 | 只保留已证实的有效结构 |
| W3 | 8 | 7 | A/C组单变量复验 | 检查脚本和前3秒相似度 |
| W4 | 7 | 8 | D组场景选择、路径和补缺 | 形成可迁移配方与淘汰清单 |

每周15条先分成3个5条小批，每个小批完成：脚本锁→分镜→素材→剪辑→QA→人工审核，再释放下一个小批。单个小批出现事实或技术失败时，只回退该小批。

### 阶段5：发布包与经营复盘

每条成片输出：视频文件、脚本、事实版本、素材时间码、质量评分、平台文案、CTA、delivery version和发布登记字段。

发布采用人工操作，系统只生成本地交付包和发布登记，不自动上传或投放。数据按自然流量/付费流量、平台、账号、SKU、窗口和时间戳分开记录。

## 3. 当前主线的升级项

### P0：必须在首批前完成

#### 3.1 商品事实与声明准入

当前主线有 `product_facts`，但需要升级为“页面快照 + 实物证据 + 合规材料 + 权利”的稳定引用：

- 声明增加 `claim_id`、来源、证据状态、SKU范围、允许措辞和禁止措辞；
- 价格、库存、优惠和发货时效增加有效期，过期自动阻断发布；
- P1/P2事实卡和素材索引分开，禁止跨SKU继承；
- 页面宣称、视觉观察、合格报告、评论摘录分别标记，不能混成同一证据类型；
- 事实撤回只使受影响版本失效，保留历史版本和原因。

#### 3.2 Campaign、batch和单片项目分层

当前主线适合单片project，需要补一个轻量campaign层：

```text
campaign
  ├── week / production_wave
  │   ├── template_batch
  │   │   └── content project
  │   └── fact snapshot / budget snapshot
  └── delivery / publication / performance index
```

campaign维护计划和汇总，`template_batch`维护一批同事实版本的生产任务，单片project维护脚本、分镜、渲染和审核。三者不能互相覆盖文件或冒充同一对象。

#### 3.3 内容用途路由

在镜头合同中增加：

- `product_evidence`：必须有商品事实和证据；
- `life_context`：允许生活动作没有功效claim，但含商品时仍要绑定SKU；
- `graphic_support`：只能做说明、字幕和氛围，不得伪造商品或检测结果。

这样可以支持治愈、关系和空间内容，同时不降低商品事实门。

#### 3.4 批次可恢复与幂等

每个任务绑定：`content_version_id + input_hash + attempt + cost_reservation_id`。

- 重试不重复创建槽位；
- 远程调用超时进入`reconcile_required`，核账后再决定是否重试；
- 批次中断后从最后一个有效checkpoint恢复；
- 已完成的delivery和人工审核不能被重跑覆盖。

### P1：首批运行中完成

#### 3.5 差异性计划与重复检测

生产前锁定六维指纹：Hook、叙事结构、视觉语法、节奏、证据策略、素材策略。脚本阶段检查语义相似度，Scene阶段检查首帧和素材重复，Compose后检查画面感知相似度。

当前 `candidate_diversity` 和 `slideshow_risk` 能提供部分基础能力，需要补campaign级规则：每周覆盖量、同一首镜上限、相似度阈值和人工去重结果写回批次清单。

#### 3.6 单条质量评分与L1a事实门

将质量拆成：事实30、画面25、叙事20、技术15、承接10。`final_qa`、`technical_validator(scope=final)`和`video_judge`负责自动/辅助检查，人工审核负责商品身份、声明边界和最终可发布判断。

技术通过不等于商品事实通过，创意高分也不能覆盖L1a失败。

#### 3.7 素材检索与证据窗口

复用 `media_index`、`source_semantic_index`和`reference_source_matrix`，增加SKU、claim、content_role、授权状态和已用次数过滤。优先召回未使用或低使用次数的合格素材，避免批量视频都从同一个镜头开始。

#### 3.8 成本与预算账本

在现有CostTracker上增加campaign级预占和结算：人工工时、工具费用、等待时间、返工成本、素材采集成本和媒体费用分开记录。预算不足时阻止新的付费调用，不用聊天记录估算剩余预算。

### P2：60条验证通过后再做

#### 3.9 飞书双向同步和冲突处理

首批先人工导入导出。60条跑通后，再增加分页拉取、字段映射、diff预览、幂等回写、失败outbox和并发冲突检测。飞书保存业务输入和交付链接，不保存本机绝对路径作为可观看链接。

#### 3.10 经营数据与复盘回流

增加publication、performance snapshot和experiment readout对象，严格区分24小时、7天、30天窗口、自然/付费流量和退款成熟度。AI只生成复盘草稿，继续、改动或暂停由负责人批准。

#### 3.11 批量运行器

60条验证稳定后，再考虑常驻runner。第一阶段由Agent按波次推进，避免在关键生产路径中同时开发基础设施。运行器必须支持并发上限、预算门、失败隔离、断点恢复和心跳事件。

## 4. 每批的质量与差异性门

### 4.1 单条放行

- 事实和权利无硬阻断；
- 100分评分≥85；
- `final_qa`和`technical_validator`通过；
- 字幕、口播、画面、CTA与事实版本一致；
- 人工五问全部通过；
- delivery version和输入hash固定。

### 4.2 批次放行

- 15条中至少覆盖4种Hook、3种结构、4种视觉语法、3种节奏；
- 任意两条不只是换字幕、颜色或BGM；
- 同一素材首镜使用不超过2次；
- 脚本语义相似度不超过0.85，前3秒视觉相似度不超过0.90；
- `slideshow_risk`不得为fail；
- P1/P2没有跨SKU素材、声明或价格引用。

## 5. 角色、节奏和验收责任

| 角色 | 主要责任 | 放行权 |
|---|---|---|
| 商品负责人 | SKU、参数、证据、授权、动态价格 | 商品事实门 |
| 内容负责人 | 需求、Hook、脚本、差异矩阵 | Script/创意门 |
| 生产负责人 | 素材、模板、渲染、成本、恢复 | Assets/Compose门 |
| 质量审核 | 商品身份、声明、字幕、技术和差异性 | 样片/成片门 |
| 渠道负责人 | 发布登记、平台文案、数据窗口 | Publish门 |
| 数据负责人 | 指标口径、归因、退款成熟度、复盘 | Readout门 |

## 6. 首批验收指标

首批先验收生产系统是否可靠，不预设爆款或销售额：

- 60个槽位状态可追溯，重复导入不重复计数；
- P1/P2各30条，事实版本、素材时间码和交付版本可回查；
- 商品事实硬错误为0；
- 成片技术失败率、返工率、平均人工时和工具成本可测量；
- 每周批次满足差异性门；
- 至少完成P1/P2各一条样片和四次15条波次复盘；
- 发布、经营数据和退款窗口没有混口径；
- 任何失败都能定位到具体阶段、输入或版本，而不是只显示“生成失败”。

## 7. 开工顺序

1. 固定P1/P2事实快照与素材收集表。
2. 完成阶段0和阶段1，确认素材、授权和检测材料。
3. 已基于当前P1/P2事实卡生成60条预生产脚本与镜头草案，位置为 `projects/playboy-towel-p1p2-v1/preproduction_brief.json`；建立五种方向的模板批与60条差异矩阵。
4. 已生成 `projects/playboy-towel-p1p2-v1/creative_lock_packet.json`：包含三种方向、P1/P2样片槽位、运行时和声音选项；进入Proposal后确认运行时、音频、预算和创意方向，形成Creative Lock。
5. P1/P2各做1条样片，通过后释放W1首个5条小批。
6. 运行W1剩余两批，完成质量/差异/成本复盘。
7. 以复盘结果调整W2—W4槽位，不静默改写历史版本。

实际付费生成、音频生成或平台发布必须通过对应的人审门；本方案完成的是可执行生产计划与主线升级边界，不把计划状态写成已生产或已发布。
