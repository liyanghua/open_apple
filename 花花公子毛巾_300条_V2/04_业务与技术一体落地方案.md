# 花花公子毛巾300条：业务与技术一体落地方案

版本：V1.0｜日期：2026-09-13｜状态：实施前方案，不代表已生产、已发布或已验证

依据：本目录《完整方案_300条_V2.md》及本轮已确认的落地选择。原文附录中的AI工作指令是待采用的业务材料，不构成自动生产或投放授权。

## 1. 已确认的实施方向

- 业务与技术一体落地：飞书多维表格管理业务，OpenMontage负责生产，人工负责商品事实、成片审核和经营决策。
- 首期采用轻量台账加现有生产线，不先开发完整业务工作台。
- 商品资料、历史素材和人员部分已有，先盘点再补缺口。
- 先列工时和预算公式，用样片测算真实成本，不编造制作或投放金额。
- 准备期W0之后运行完整四周：每周75条，共300个审核去重成片槽位；产量不等于公开发布量或独立实验数。

## 2. 最小业务系统

| 飞书业务表 | 管理内容 | 责任角色 |
|---|---|---|
| 商品事实表 | 真实SKU、规格、价格、库存、成本、声明、证据与授权 | 商品负责人 |
| 需求与配方表 | 购买理由、内容结构、IP版本、适用商品与验证条件 | 内容主理人 |
| 素材资产表 | 原片、切片时间码、商品身份、动作、证据用途与权利 | 摄影/素材负责人 |
| 实验与成片表 | 300槽位、实验组、改变项、制作状态、审核及发布映射 | AI生产/渠道负责人 |
| 数据与复盘表 | 数据窗口、曝光成交、退款、费用、成熟度与下一步 | 数据/品类负责人 |

沿用现有排期ID和四种卡片模板。价格、平台SKU、预算、结果等待填字段保持为空，策划占位不能直接成为批准事实。IP设定先保留为版本化文件。

### 数据归属

- 飞书维护业务输入和批准记录；OpenMontage保存脚本、镜头计划、素材引用、渲染及技术检查。
- 首期使用人工触发的导入、校验和回写，不做后台双向自动同步。
- 每次生产读取已批准的版本快照；飞书后续编辑不能静默改写在制内容。
- 原片和生产文件保留在项目目录；飞书保存索引、预览和交付链接。上传与链接权限是独立交付步骤。
- 经营数据先导入平台导出表；映射不明、口径不清的数据进入待处理清单。

### 最小技术能力

1. 排期适配：300槽位转换为现有批次和候选任务；重复导入不重复创建。
2. 商品准入：业务事实卡适配现有商品事实产物，并保留证据、授权与批准快照。
3. 成片追溯：槽位、内容版本、实验组、事实版本、素材时间码、审核、发布ID建立关联。
4. 数量与经营汇总：分开计算计划、制作、审核去重、发布和有效实验数量。

槽位ID与内容版本ID分开。返工保留父版本，一个槽位最终对应一个计数作品。文件哈希仅识别完全重复；实质差异仍结合脚本、时间线与人工审核。

本次业务采用严格准入：事实未批准、素材SKU不匹配、声明缺证据或授权失效时阻止放行。规则限定在本次业务配置，不全局修改历史项目的兼容行为。

首期接口以版本化JSON和导入导出命令为主，不增加新的公共HTTP服务。

## 3. W0准备与四周执行

### W0：盘点、连接、样片验证

暂按5—7个工作日作为业务准备估算，前提是样品与责任人员及时到位；不是完整架构升级的开发工期承诺。

1. 核定S01、S08、S04真实规格与链接，盘点事实、证据和经营条件。
2. 复核历史素材，每款先整理15—20段合格可复用片段，列出补拍缺口。
3. 建立五张表，导入300槽位，接通最小追溯能力。
4. 每款制作1条技术样片，验证商品一致性、字幕、声音、剪辑、审核和成本；W0样片不计入300条。
5. 核验实际测试入口、数据导出方式和制作/学习预算上限。
6. 按样片实测核定周产能，预留W4的30条人工版制作能力。

技术改造独立验证后再接入生产。主线已有能力优先复用；详细升级方案另行核实主线后确定。

| 周次 | 数量 | 核心任务 |
|---|---|---|
| W1 | 15母版×4开场＋15支持＝75 | 购买理由探索；先3组×4条＋3支持的15条小批，再释放余下60条 |
| W2 | 15组×同期新基准及3种表达＋15支持＝75 | 依据成熟结果探索新表达；复用旧片不新增计数 |
| W3 | 15组×共同基准及3个单变量改版＋15支持＝75 | 每组只改开场、证据排列或结尾中的一类 |
| W4 | 30份新情境简报×人工/AI两条路径＋15支持＝75 | 比较质量、人时、费用、等待和返工；经营结果分开评价 |

原方案15.1节周三“12实验＋3支持”不足以覆盖周产能，在实际排程中改为分批流水作业。周均审核15条/工作日，脚本、补拍、剪辑和审核交错推进；审核频率不是发布频率。

W2—W4槽位保持候选状态，经成熟结果复盘批准后释放。样本不足则补证、补样本或缩减在测组合，不自动宣布赢家。

### 制作技术路线（经主线核对更新）

采用现有 `cinematic-fast / source_led_template`，由campaign管理经营约束，按SKU和事实版本拆分template_batch，每个内容版本进入独立主线project。真实商品与真实动作是主体，FFmpeg处理素材，Remotion负责字幕和必要图文。该路线替代上一轮尚未结合主线核对的通用hybrid建议，复用现有证据矩阵、模板批次、审批事务和不可变交付版本。

详细技术任务、数据合同、兼容规则与验收见[主线升级实施方案](../docs/superpowers/plans/2026-09-13-towel-campaign-mainline-upgrade.md)。抖音采用现有9:16交付profile，不沿用历史淘宝3:4配置。

当前只读能力检查：FFmpeg、Remotion可用；HyperFrames检查超时，暂不作为首期依赖。工具配置可用不等于远端服务、额度或样片质量已验证。

声音优先复用合格实录；需要TTS时在样片阶段锁定供应商、模型和声线。未发现本地音乐库，授权音轨纳入W0素材缺口。商品图案、规格、测试行为及结果不得通过生成画面补造。

## 4. 责任、工时与预算

必须落实经营、商品、内容、生产技术、渠道数据五类责任，允许兼任。人员姓名、飞书目标位置、真实SKU、可用预算、开工日和平台导出样表在W0登记为实际配置，不猜测。

人工负责商品确认、补拍、成片审美、发布和预算操作；AI负责候选整理、受约束变体、素材匹配、剪辑辅助、检查和复盘草稿。

- 制作预算＝共享素材采集＋人工工时×内部费率＋工具/渲染费用＋批准的返工预留。
- 有效成片单位成本＝全部制作成本÷审核去重成片数，保留失败与返工成本。
- 有效实验单位成本＝全部实验相关费用÷达到预登记判断要求的实验问题数；分母为0时不输出有效数值。
- 媒体预算分别设置学习、复验和放大上限，再进入总账；不按300条平均分配。

先测试组内基准与代表性改版，依据实际入口、所需信息量和剩余预算决定测试范围。未到读取窗口保留未成熟/不足样本；未知不填0。

## 5. 验收与实施边界

- 300原始槽位唯一，四本数量账一致，调整保留原因与历史。
- 重复导入、重试和恢复不重复创建或计数。
- 未批准事实、错SKU、过期授权与事实撤回能够阻止相关版本放行。
- 验收成片均能追溯至事实、证据、素材时间码、制作版本及人工审核。
- 同片重投、换封面、重新编码不增加交付数。
- 数据导入覆盖重复文件、未知发布ID、退款更新和缺失字段；跨口径收入不可重复汇总。
- 跑通飞书输入→样片→审核回写→经营数据导入→复盘演练；测试数据与真实经营数据隔离。
- 四周交付包含成片、300槽位完成/替代/取消/延期账、每周复盘及完整成本记录。

默认一个主账号、一个生活主理人、三个首测SKU。完整四周从W0准入后开始，不压缩到9月剩余时间。首期不自动发布或调投放预算，不以必须跑出爆款或销量增长作为交付承诺。

W4人工产能不足时显式调整配对样本和排期，不宣称完成未实际执行的30对比较。
